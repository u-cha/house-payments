# Матрица прослеживаемости

Связывает требования [brief.md](brief.md) с модулями, сущностями, инвариантами,
решениями, сценариями и проверками. Строка без проверки — незакрытое требование;
проверка без требования — избыточная работа.

Обозначения: **Модуль** — владелец функциональности; **Таблицы** — из
[domain/model.dbml](domain/model.dbml); **INV** — [domain/invariants.md](domain/invariants.md);
**ADR** — [architecture/adr/](architecture/adr/README.md); **UX** — [ux/scenarios.md](ux/scenarios.md);
**Эпик** — [roadmap.md](roadmap.md).

## 5. Риски и ограничения

Полные формулировки, обоснование, остаточные риски и условия пересмотра —
[risks.md](risks.md). Здесь — краткая сводка принятых решений.

| ID | Риск / ограничение | Решение (2026-11-04) | Владелец |
|---|---|---|---|
| R-01 | Один файл данных растёт до гигабайт (вложения) | Только сжатая копия вложения; предупреждение при 2 ГБ; архив после v1 | техлид |
| R-02 | Одна резервная копия может быть перезаписана испорченным состоянием | Две копии (текущая и предыдущая) + проверка целостности | пользователь |
| R-03 | `better-sqlite3` — нативная зависимость, сборка под три ОС | CI GitHub Actions: macOS, Windows, Linux | техлид |
| R-04 | Подпись Windows и нотаризация macOS требуют сертификатов | Тестовые сборки без подписи; сертификаты к релизу 1.0 | пользователь |
| R-05 | Синхронизация отложена; ожидания пользователя могут расходиться | Одно устройство; синхронизация — после v1 (M5) | пользователь |
| R-06 | Импорт CSV зависит от формата выгрузки поставщика | CSV-импорт вне первой версии | пользователь |
| R-07 | Модель правил напоминаний может требовать уточнения окон | Простые настраиваемые окна с умолчаниями; без конструктора | пользователь |
| R-08 | Linux-дистрибутивы фрагментированы | Ubuntu/Debian: AppImage + deb; остальные — AppImage | техлид |
| R-09 | Точность локального OCR на плохих фото и рукописных квитанциях | 90 % на чётких печатных; ручная правка; облако не по умолчанию | техлид |
| R-10 | Шаблоны поставщиков требуют сопровождения при смене формата квитанций | Модуль настройки шаблонов в v1 (FR-20, E-15): пользователь создаёт шаблон по скану; версии не перезаписываются; без самообучения (INV-23) | пользователь |

## 6. Что не покрыто осознанно

- Онлайн-оплата, интеграции с личными кабинетами поставщиков, ГИС ЖКХ — вне
  scope (brief §3); архитектура не резервирует под них модули.
- Пени и перерасчёты по нормативам — после первой версии; модель позволяет
  добавить услугу и начисление без смены стиля.
- Юридически значимая квитанция — OQ-05 закрыт: не требуется; личный архив
  хранит сжатую копию, `sha256`, дату и аудит.
- Импорт начислений из CSV — после первой версии (R-06); модель и ADR-0004
  сохраняют задел.
