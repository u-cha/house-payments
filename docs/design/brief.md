# Бриф: архитектура приложения house-payments

Статус: **proposed** (на ревью у владельца продукта). Владелец решения: пользователь-собственник.
Дата: 2026-11-04. Предыдущая проработка (SaaS для управляющих компаний) сохранена в
[archive/saas-2026-11-04/](../../archive/saas-2026-11-04/design/README.md) и не является
действующей: продукт переопределён.

Документ фиксирует границы задачи, требования, критерии приёмки и точки реализации.
Остальные артефакты (`domain/`, `architecture/`, `ux/`, `roadmap.md`) выводятся из этого
брифа и ссылаются на его идентификаторы.

## 1. Назначение

**house-payments** — локальное настольное приложение для частного лица, которое владеет
одним или несколькими объектами недвижимости (квартира, дом, машиноместо,
земельный участок) и ведёт учёт платежей за жилищно-коммунальные услуги: начисления и квитанции от поставщиков, свои платежи, долг и
переплату, показания счётчиков и сроки, напоминания, отчёты и подтверждающие документы.
Квитанции можно вносить вручную или загружать **фото, сканы и PDF с локальным
распознаванием и обязательным подтверждением**.

Приложение работает офлайн, данные хранятся в одном переносимом файле на устройстве
пользователя. Установка — обычный установщик под Windows, macOS и Linux; Docker, сервер,
администратор и подписка не нужны.

### Решение A-01 (закрыт 2026-11-04)

> Продукт предназначен **частному лицу — собственнику объектов недвижимости**, а не
> организации
> (УК, ТСЖ, расчётному центру). В первой версии — **один профиль владельца**; модель
> данных сразу поддерживает профили и роли, чтобы позже добавить членов семьи без
> переделки модели. Идентификаторы глобально уникальны, журнал изменений ведётся с
> первого дня — это задел для будущей синхронизации.

Следствия: организации, изоляция тенантов, банковские выписки, массовые начисления по
тысячам лицевых счетов и экспорт в 1С выведены из scope. Вместо них — поставщики,
лицевые счета, счётчики, напоминания и вложения (сканы квитанций).

### Зона развития (после первой версии)

- Синхронизация между устройствами (компьютер + телефон) через облако.
- Мобильный клиент.
- Профили членов семьи и роли `member` (модель готова, режим не входит в v1).
- Шифрование файла данных и архив по годам.
- Импорт начислений из CSV и данных из личных кабинетов поставщиков (распознавание
  сканов и фото, включая PDF, уже в v1).
- Совместное ведение с другими собственниками (не только члены семьи).

## 2. Заинтересованные стороны

| Сторона | Интерес | Критичность |
|---|---|---|
| Пользователь-собственник (роль `owner`) | Ввести данные быстро, видеть долг и переплату, не потерять документы | Критическая |
| Член семьи (роль `member`, после v1) | Вносить показания и платежи, видеть историю, не иметь доступа к настройкам | После первой версии |
| Поставщик услуг (УК, ТСЖ, РСО) | Источник начислений и квитанций; интеграции в MVP нет | Средняя |
| Разработчик/сопровождающий | Понятный код, воспроизводимая сборка, переносимые данные | Средняя |

## 3. Границы

### В scope первой версии

- Объекты пользователя (квартира, дом, машиноместо, земельный участок и другие типы),
  доли владения и редактируемый справочник типов.
- Поставщики услуг и лицевые счета (объект × поставщик).
- Услуги и версионируемые тарифы.
- Начисления за расчётный период: ручной ввод и ввод по шаблону (импорт CSV — зона
  развития, решение R-06).
- Приём квитанций фото, сканом или PDF, локальное распознавание, подтверждение
  результата пользователем и создание начислений/квитанции из подтверждённых данных.
- Модуль настройки шаблонов квитанций: пользователь сам создаёт и версионирует
  шаблон по скану нового формата, размечая области полей мышью (R-10, FR-20).
- Квитанции/счета: формирование, фиксация, неизменяемость после фиксации, аннулирование.
- Платежи: ручная регистрация, распределение по квитанциям (FIFO и вручную), долг и переплата.
- Счётчики: установка, дата поверки, срок годности, показания, передача показаний.
- Напоминания: срок оплаты, срок передачи показаний, срок поверки, отметка о внесении
  показаний в личный кабинет поставщика.
- Вложения: фото и сканы квитанций, чеков и актов.
- Отчёты и графики расходов по периодам, услугам и объектам.
- Профиль владельца `owner` и локальный вход; модель профилей/ролей готова к членам
  семьи (сам режим — после первой версии).
- Аудит изменений: кто, когда, что и почему изменил.
- Экспорт/импорт, резервное копирование, перенос файла данных на другое устройство.

### Вне scope первой версии (осознанно отложено)

- Онлайн-оплата и интеграция с банками/эквайрингом.
- Автоматическая загрузка начислений из личных кабинетов поставщиков.
- Импорт начислений из CSV (решение R-06): квитанции вносятся фото/сканом, PDF
  или вручную.
- Синхронизация между устройствами и мобильное приложение.
- Профили членов семьи и роли `member`; шифрование файла; архив по годам.
- Юридически значимые квитанции, электронная подпись, судебная работа.
- Пени и перерасчёты по нормативам.
- Бухгалтерский и налоговый учёт, экспорт в 1С.

### Ограничения

| ID | Ограничение |
|---|---|
| C-01 | Локальность: приложение работает без сети; данные — в файле на устройстве пользователя. |
| C-02 | Деньги — только целые минорные единицы (копейки), без плавающей точки. |
| C-03 | Расчётный период — `YYYY-MM`. |
| C-04 | Персональные данные минимизируются и остаются локально; пароли профилей хранятся только как хеш; журналы не содержат PII. |
| C-05 | Импорт, повторные операции и будущая синхронизация обязаны быть идемпотентными. |
| C-06 | Стек: TypeScript, Electron, React, SQLite; модульный монолит в одном процессе. |
| C-07 | Диаграммы — только из текстовых источников (`.mmd`, `.dbml`), рендер детерминирован. |
| C-08 | Платформы: Windows 10+, macOS 12+, Linux (Ubuntu 22.04+/Debian 12+, другие дистрибутивы — через AppImage); установка без прав администратора. |
| C-09 | Переносимость: один файл данных, документированная схема, экспорт CSV/XLSX/JSON, резервная копия; файл переносится между устройствами и версиями приложения. |
| C-10 | Локальная аутентификация с профилем владельца; модель профилей и ролей готова к членам семьи (режим — после первой версии). |
| C-11 | Распознавание квитанций выполняется локально, без отправки изображений в сеть; распознанные данные не создают финансовых документов без подтверждения пользователем. |

## 10. Роли исполнения

Это роли **процесса разработки**, а не приложения; технические роли могут
исполняться агентами.

| Роль | Ответственность |
|---|---|
| Пользователь | Что нужно, приоритеты, приёмка; владелец продуктовых рисков. |
| Техлид | Архитектура, границы, ревью, fitness functions; владелец технических решений. |
| Разработчик | Реализация, тесты, сборка; может быть человеком или агентом. |
| Интеграции | Форматы импорта, шаблоны поставщиков, внешние источники. |
