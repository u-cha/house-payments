# ADR-0009: Кросс-платформенное настольное приложение и установщики

## Статус

`proposed`, 2026-11-04. Владелец решения: пользователь-собственник.

## Контекст

- C-08: поддерживаемые платформы — Windows 10+, macOS 12+, Linux (Ubuntu 22.04+/
  Fedora 36+); установка без прав администратора.
- Пользователь просил «приложение с установкой, чтобы не знать, что такое Docker»:
  установщик, а не сервер и не набор инструкций.
- Приложение локальное (ADR-0001), с файлом данных (ADR-0008), без онлайн-сервисов.
- Пользователь может быть неопытен: установка и обновление должны быть
  предсказуемыми, ошибки — понятными, данные — не в системных папках.

Силы: охват платформ (тянет к трём ОС), простота (тянет к одной), стоимость
подписи (тянет к одной), требования магазинов приложений (тянет к упаковке).

## Рассмотренные варианты

### 1. Один установщик под Windows/macOS/Linux на Electron (выбран)

Один кодовый базис, три установщика; per-user установка; автоматические обновления.

**Плюсы:** покрывает все три платформы без отдельных кодовых баз; одинаковый
рендеринг (встроенный Chromium); зрелые инструменты установки и обновления;
не требует прав администратора; подпись и нотаризация поддерживаются.

**Минусы:** размер установщика и потребление памяти выше, чем у нативных решений;
нужны подпись Windows и нотаризация macOS; Linux-дистрибутивы фрагментированы.

### 2. Только Windows

**Плюсы:** минимальная стоимость и лучшая поддержка.

**Минусы:** отсекает macOS и Linux; противоречит C-08. Отклонён.

### 3. Веб-версия вместо установки

**Плюсы:** ничего не устанавливать.

**Минусы:** нужен сервер и интернет; данные не локальны; противоречит C-01.
Отклонён.

### 4. Tauri (Rust-оболочка) или Flutter

**Плюсы:** меньше размер и память; нативный рендеринг у Flutter.

**Минусы:** Tauri добавляет Rust и различия webview между ОС; Flutter добавляет Dart
и отдельную экосистему для desktop; команда и стек ориентированы на TypeScript
(ADR-0010). Отклонены для первой версии; могут быть пересмотрены по ADR.

### 5. PWA (устанавливаемый сайт)

**Плюсы:** один код, установка из браузера.

**Минусы:** нужен хостинг; офлайн-хранилище ограничено и зависит от браузера;
нет прямого доступа к файлу данных; не соответствует «файл данных у пользователя».
Отклонён.

## Решение

1. **Поддерживаемые платформы первой версии:**
   - Windows 10 (22H2+) и Windows 11, x64; установщик NSIS `.exe`, per-user, без UAC;
   - macOS 12+ (Apple Silicon и Intel), `.dmg` с universal-бинарём, нотаризация;
   - Linux x86_64: AppImage (универсально) и `.deb` для Ubuntu 22.04+/Debian 12+;
     Fedora 36+ — через AppImage.
2. **Установка** не требует прав администратора; данные — в профиле пользователя
   (`%APPDATA%`, `~/Library/Application Support`, `~/.local/share`).
3. **Обновления:** `electron-updater` по подписанному каналу; проверка версии не
   чаще раза в сутки; установка по действию пользователя, без принудительного
   перезапуска; доступна ручная установка новой версии поверх старой.
4. **Подпись:** Windows — Authenticode; macOS — Developer ID и нотаризация. Без
   подписи приложение работает, но ОС показывает предупреждение; это допустимо
   только для тестовых сборок. Сертификаты покупаются **к релизу 1.0** (R-04):
   до этого разработка и тестовые сборки — без подписи; неподписанная сборка не
   получает статус стабильной. Бюджет и данные для оформления — за пользователем.
5. **Сборка:** GitHub Actions на macOS (разработка), Windows и Linux (использование)
   собирает и тестирует приложение, включая нативную зависимость `better-sqlite3`
   (R-03); оттуда же публикуются релизные установщики.
6. **Совместимость файла данных** не зависит от платформы: один формат
   (ADR-0008), перенос между Windows/macOS/Linux поддержан.
7. **Архитектура:** x64 для Windows и Linux в первой версии; arm64 для Windows —
   после проверки спроса.

## Последствия

**Положительные:**

- Пользователь скачивает установщик и работает; никакого Docker и сервера.
- Один код и одинаковое поведение на всех платформах.
- Данные переносимы между платформами без конвертации.
- Обновления не требуют действий администратора.

**Отрицательные:**

- Размер установщика ~100–150 МБ; память приложения выше нативного.
- Нужны сертификаты подписи и нотаризация macOS; это деньги и процесс (R-04).
- Linux: несколько форматов пакетов, нет единого магазина; целевая поддержка —
  Ubuntu/Debian, остальные — через AppImage (R-08).
- Старые версии ОС (Windows 7/8, macOS 11) не поддерживаются.
- Нативная сборка под три ОС требует CI и периодических обновлений зависимостей (R-03).

**Запрещено:** требовать права администратора; писать данные в системные папки;
ломать совместимость формата файла между платформами; распространять
неподписанные сборки как стабильные.

## Условия пересмотра

- Появляется требование мобильного клиента (OQ-04) — рассматривается отдельный
  клиент или PWA, ADR-0010 пересматривается.
- Размер и потребление памяти становятся проблемой на слабых устройствах —
  рассматривается Tauri с тем же доменным кодом.
- Магазины приложений (Microsoft Store, Mac App Store) становятся каналом
  распространения — меняется упаковка и правила обновлений.
- Windows arm64 или Linux arm64 становятся массовыми — добавляются сборки.
- GitHub Actions перестаёт быть доступным или появляются ограничения — сборка
  переносится на локальные машины/другой CI (R-03).
