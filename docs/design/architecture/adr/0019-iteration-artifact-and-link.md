# ADR-0019: Пересборка и ссылка на артефакт по итогу итерации

## Статус

`accepted`, 2026-11-06. Владелец решения: пользователь-собственник. Требование
сформулировано владельцем 2026-11-06 в сессии по задаче `t-mw4vug2v-6feuj1`:
по итогу каждой итерации должен быть пересобранный экземпляр приложения в
известном месте и ссылка на него. Дополняет
[ADR-0018](0018-latest-runnable-artifact.md): 0018 отвечает на вопрос «где искать
запускаемый экземпляр», 0019 — «когда его пересобирать и как передавать ссылку».
Связан с [ADR-0009](0009-cross-platform-desktop-and-installers.md) (установщики),
[ADR-0013](0013-repository-docs-and-versioning.md) (репозиторий) и
[ADR-0016](0016-ci-triggers-on-pull-request.md) (CI на PR в `main`).

## Контекст

- ADR-0018 закрепил место (`release/` локально, CI-артефакты `latest-*` и
  `pnpm app:latest` с M0-13), но требует запускаемого результата только на
  гейтах V0–V3. Между гейтами итерации заканчивались словами «код готов».
- Сдача M0-09 (гейт V1) прошла без собранного приложения: ручная проверка шла
  через CDP на `pnpm dev`, скриншоты лежали вне репозитория. Пользователь
  получил отчёт, но не экземпляр, который можно запустить и потрогать.
- Локальное имя артефакта содержало версию (`house-payments-0.0.0-arm64.dmg`),
  поэтому «известное место» менялось вместе с версией: одна и та же ссылка не
  годилась дважды.
- Термин «итерация» в артефактах не определён: есть веха, эпик, задача доски и
  гейт. Без определения правило нельзя проверить и нельзя поручить агенту.
- До M0-13 CI-артефактов и `pnpm app:latest` не существует — единственный
  запускаемый экземпляр даёт локальная сборка. После M0-13 источником истины
  становится артефакт зелёного `main` (ADR-0018, п. 4).

Силы: свежесть экземпляра (тянет к сборке на каждый шаг) против времени и шума
(тянет к сборке только на гейтах); предсказуемость ссылки (тянет к стабильному
имени без версии) против информативности имени (тянет к версии в имени).

## Рассмотренные варианты

### 1. Итерация = задача с кодом: пересборка и ссылка в сдаче (выбран)

Каждая задача доски, меняющая код приложения, завершается пересборкой в
`release/` со стабильным именем и ссылкой на артефакт в отчёте. После M0-13
добавляется ссылка на артефакт CI.

**Плюсы:** пользователь всегда получает запускаемый экземпляр ровно того
состояния, которое описано в отчёте; ссылка не меняется от версии к версии;
ошибка сборки обнаруживается на итерации, а не на гейте.

**Минусы:** каждая итерация тратит время на сборку; артефакт отражает рабочее
дерево ветки, а не `main`; дисциплину надо удерживать правилом, а не памятью.

### 2. Только гейты V0–V3 (как в ADR-0018)

**Плюсы:** минимум сборок, ничего дополнительно делать не нужно.

**Минусы:** ровно та проблема, из-за которой решение принимается: между гейтами
пользователь не может запустить то, что ему сдали; V3 наступает только после
M0-13.

### 3. Пересборка на каждое изменение или пуш

**Плюсы:** максимальная свежесть.

**Минусы:** сборка на каждый коммит и пуш — это минуты на каждую правку и
десятки перезаписанных `.dmg` в день; ссылка теряет смысл, потому что за время
проверки появляется новая.

### 4. Ссылка только на последний CI-артефакт, без локальной сборки

**Плюсы:** проверяется ровно `main`, воспроизводимо.

**Минусы:** до M0-13 ссылки нет вообще — требование не работает сегодня; каждая
итерация ждёт прогона CI и merge, что замедляет цикл правок.

## Решение

1. **Определение итерации.** Итерация — завершённая задача доски, меняющая код
   приложения (`apps/**`, `packages/**`, конфигурация сборки и упаковки).
   Задача, которая не меняет код приложения (документация, проверки
   артефактов, CI-конфигурация без влияния на состав сборки), пересборки не
   требует и ссылки не даёт.
2. **Пересборка — обязательный шаг завершения.** Итерация с кодом заканчивается
   командой `pnpm dist:mac` (или будущей кросс-платформенной заменой). Сборка
   пишет в единственный `release/` и перезаписывает предыдущий результат
   (ADR-0018).
3. **Стабильное имя и известное место.** Артефакт macOS называется
   `release/house-payments-mac-arm64-latest.dmg`: без версии в имени, чтобы
   ссылка была одной и той же на каждой итерации. Имя и путь закреплены
   конфигурацией `electron-builder` и проверяются тестом.
4. **Ссылка обязательна.** В отчёте по задаче и/или комментарии к ней —
   markdown-ссылка относительным путём от корня репозитория:

   ```markdown
   [house-payments-mac-arm64-latest.dmg](release/house-payments-mac-arm64-latest.dmg)
   ```

   «Собрано» без ссылки завершением итерации не считается.
5. **Переключение источника истины на M0-13.** До M0-13 (CI не публикует
   артефакты, `pnpm app:latest` не существует) единственный экземпляр —
   локальная сборка из п. 2–3. После M0-13 приёмка идёт по артефакту последнего
   зелёного прогона `main` (ADR-0018, п. 4): `pnpm app:latest` кладёт его в
   `.app-latest/`, а в отчёте указываются ссылка на `.app-latest` и URL
   артефакта CI. Локальная сборка остаётся допустимой дополнительной ссылкой,
   но помечается «локальная сборка» — запрет ADR-0018 выдавать её за «последний
   экземпляр» сохраняется.
6. **Что именно собрано.** Локальная сборка отражает рабочее дерево ветки
   задачи, то есть состояние этой итерации, а не `main`. Для промежуточной
   итерации это и есть проверяемый экземпляр; для приёмки гейта источник
   истины — п. 5.
7. **Проверяемость.** Имя и путь артефакта закреплены тестом репозитория,
   правило продублировано в [AGENTS.md](../../../../AGENTS.md) §5 (критерии
   готовности) и [roadmap.md](../../roadmap.md) §3 (гейты и артефакты). Смена
   имени или места без обновления ADR-0019, README и теста считается ошибкой.

## Последствия

**Положительные:**

- Пользователь на каждой итерации получает запускаемый `.dmg` и одну и ту же
  ссылку на него; не нужно искать «какая сборка свежая».
- Ошибки упаковки ловятся на итерации, а не на гейте V3.
- Правило проверяемо: имя и путь закреплены тестом, критерий готовности — в
  AGENTS.md, а не в памяти участников.

**Отрицательные:**

- Каждая итерация с кодом тратит время на сборку (минуты, зависит от машины).
- Локальный артефакт отражает ветку, а не `main`; при параллельных ветках
  последняя сборка может быть не из `main`.
- Ссылка на локальный файл живёт до следующей сборки; истории сборок до 1.0 нет
  (ADR-0018).

**Запрещено:** сдавать итерацию с кодом без пересборки и ссылки на артефакт;
менять имя или место артефакта без обновления ADR-0019, README и теста;
копить версионные сборки в `release/`; выдавать локальную сборку за артефакт
зелёного `main` после M0-13.

## Условия пересмотра

- M0-13 закрыт: CI публикует `latest-*`, `pnpm app:latest` работает — источником
  истины для приёмки становится CI-артефакт, локальная сборка остаётся
  вспомогательной (п. 5).
- Появляются локальные сборки под Windows и Linux: имя и путь артефакта
  расширяются по платформам, ADR-0019 и тест обновляются вместе.
- Сборка становится дороже 5 минут или появляется несколько параллельных
  итераций с кодом — правило пересматривается (сборка по требованию вместо
  каждой итерации).
- Релиз 1.0: версии, подписанные каналы и обновления (ADR-0009) заменяют
  `latest`, ссылка ведёт на релиз.
