## 2. Правила ведения

### Формат

Гибрид Nygard и MADR. Обязательные разделы, в этом порядке:

1. `Статус` — одно значение из списка ниже, дата, при наличии — ссылка на
   заменяющее решение.
2. `Контекст` — силы, ограничения и требования, из-за которых решение вообще
   нужно. Со ссылками на `FR-*`, `QS-*`, `C-*`, `INV-*`, `A-*`, `OQ-*`.
3. `Рассмотренные варианты` — не менее двух, у каждого плюсы и минусы.
4. `Решение` — проверяемое утверждение, а не лозунг.
5. `Последствия` — положительные и отрицательные, включая то, что запрещено.
6. `Условия пересмотра` — наблюдаемые пороги, при которых решение перестаёт быть
   верным.
7. `Ссылки` — только на существующие артефакты репозитория.

Названия разделов не переводятся на английский и не переименовываются: по ним
работают проверки.

### Статусы

| Статус | Значение | Кто меняет |
|---|---|---|
| `proposed` | Решение проработано и вынесено на ревью, но не принято | автор |
| `accepted` | Принято и обязательно к исполнению | владелец продукта |
| `rejected` | Рассмотрено и отклонено; остаётся как запись о вариантах | владелец продукта |
| `superseded by ADR-NNNN` | Заменено новым решением; текст сохраняется | автор нового ADR |
| `deprecated` | Больше не применяется, замены нет | автор |

Все ADR в этой поставке — `proposed`. Переход в `accepted` — действие ревью, а не
следствие того, что документ написан.

### Нумерация и изменения

- Номер сквозной, четырёхзначный, никогда не переиспользуется. Отклонённое решение
  остаётся в журнале.
- Принятый ADR не редактируется по существу. Изменение решения оформляется новым
  ADR с полем `Заменяет: ADR-NNNN`; в старом меняется только `Статус` и
  добавляется ссылка на замену.
- Опечатки и битые ссылки исправлять можно — это не изменение решения.
- Имя файла: `NNNN-kebab-case.md`; ссылки — относительные, из каталога `adr/`.
- Дата — ISO `YYYY-MM-DD`, дата вынесения на ревью.

ведут.
