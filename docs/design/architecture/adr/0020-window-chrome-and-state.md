# ADR-0020: Заголовок окна и сохранение состояния окна

## Статус

accepted, 2026-11-06. Принято владельцем вместе с дизайн-планом редизайна
([design-system.md](../../ux/design-system.md)).

## Контекст

Приложение вышло из гейтов M0-09/M0-11 с системной рамкой и размером окна
900×640, который не запоминался между запусками. Визуальная система
([design-system.md](../../ux/design-system.md)) требует единой шапки на всех
экранах, плотности рабочего окна и обеих тем ОС. Скилл `desktop-ui-electron`
даёт паттерны кастомного заголовка, но у них есть цена: drag-регион перехватывает
указатель, а системные кнопки окна нельзя потерять.

Ограничения:

- `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true` — без
  изменений; IPC-контракт (`src/shared/ipc.ts`) не расширяется.
- Сборка — неподписанный macOS `.dmg` (ADR-0009), но приложение должно
  запускаться и на Windows/Linux (ADR-0010).
- Пользователь работает офлайн; окно не должно «уезжать» за экран после смены
  монитора.
- Тема — системная; приложение не должно перезапускаться при её смене.

## Рассмотренные варианты

### 1. Оставить системную рамку

Плюсы: нулевой риск для доступности и платформенных конвенций, ничего не надо
поддерживать.
Минусы: шапка не срастается с навигацией, визуальная система остаётся
«браузерной», ширина окна и позиция не запоминаются.

### 2. Полностью безрамочное окно (`frame: false`) со своими кнопками

Плюсы: полный контроль над шапкой на всех платформах.
Минусы: нужно реализовать свернуть/развернуть/закрыть, повторить поведение
macOS-светофора и Windows-кнопок, не сломав клавиатуру и скринридеры; риск
потери системных функций. Для рабочей утилиты это неоправданная цена.

### 3. `titleBarStyle: 'hidden'` + `titleBarOverlay` (выбран)

Плюсы: системные кнопки остаются системными (светофор macOS, overlay
Windows/Linux), шапка становится частью интерфейса, drag-регион задаётся CSS,
объём кода минимален.
Минусы: появляется платформенная ветка в CSS и main; в обычном Chrome без
Electron светофор не виден (проверка вёрстки — с запасом слева).

## Решение

- macOS: `titleBarStyle: 'hidden'`, `trafficLightPosition: { x: 16, y: 13 }` под
  полосу 38 px. Светофор остаётся системным, приложение рисует только содержимое
  шапки.
- Windows/Linux: `titleBarOverlay` высотой 38 px с цветами текущей темы;
  содержимое шапки не заходит в зону системных кнопок (запас справа).
- HTML-шапка: `-webkit-app-region: drag`, `user-select: none`; все интерактивные
  элементы внутри — `no-drag`.
- Позиция, размер и развёрнутость окна сохраняются в
  `window-state.json` в `app.getPath('userData')`; запись — на `close` и с
  задержкой 300 ms после `resize`/`move`, у развёрнутого окна — нормальные
  границы. Восстановление принимается, только если окно пересекается с рабочей
  областью одного из текущих дисплеев не меньше чем на 120×64 px.
- Размер по умолчанию 1180×760, минимум 900×640.
- `nativeTheme.themeSource = 'system'`; renderer получает системную тему через
  `prefers-color-scheme`, main перекрашивает фон окна и overlay по событию
  `nativeTheme.updated`.
- Пользователь может переопределить тему в шапке: «светлая / тёмная / как в
  системе». Предпочтение хранится в `localStorage` (`theme.ts`), в системном
  режиме слушается смена темы ОС; по умолчанию — светлая. Новый IPC-канал для
  этого не вводится, поэтому overlay Windows/Linux в принудительной теме остаётся
  системным (ограничение зафиксировано ниже).
- Новых IPC-каналов нет: состояние окна и тема живут в main и CSS.

## Последствия

Положительные:

- Единая шапка на входе, каркасе, списке и форме; окно переживает перезапуск.
- Системные кнопки и сочетания остаются нативными; `contextIsolation` и
  preload-контракт не тронуты.
- Обе темы работают без перезапуска и без новых каналов; выбор темы доступен на
  всех экранах и переживает перезапуск.

Отрицательные и ограничения:

- Появляется платформенная ветка: `titleBarOverlay` и цвет оверлея нужно
  поддерживать для Windows/Linux.
- Файл состояния — ещё одно место, где может остаться мусор; он проверяется и
  молча игнорируется при ошибке.
- Принудительная тема, отличная от системной, не перекрашивает overlay
  Windows/Linux; для этого понадобился бы IPC-канал и отдельное решение.
- Светофор не отрисуется в браузерной проверке вёрстки — это ожидаемо.
- Скринридеры и клавиатура: шапка не должна содержать ловушек фокуса; кнопка
  «Выйти» — обычная кнопка, drag-регион не фокусируется.

## Условия пересмотра

- Если кастомная шапка ломает доступность (порядок фокуса, озвучивание) или
  системные кнопки перекрывают элементы на Windows/Linux.
- Если появляется второе окно или панель с собственным состоянием.
- Если формат `window-state.json` перестаёт быть совместимым между версиями.
