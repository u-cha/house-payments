# Архитектура house-payments: навигация и карта решений

Статус: **proposed** (ревью 2026-11-04). Владелец решений: пользователь-собственник;
исполнитель проработки — техлид; роли процесса — brief §10. Источник требований — [brief.md](../brief.md);
термины — [glossary.md](../domain/glossary.md); трассировка — [traceability.md](../traceability.md).

Этот каталог отвечает на вопрос «как устроена система и почему именно так», а не
«что она должна делать». Требования и критерии приёмки живут в брифе; здесь —
границы, зависимости, компромиссы и способ их проверки.

## 3. Карта решений

| Решение | ADR | Отклонённые альтернативы | Что даёт | Чем платим | Пересматривается при |
|---|---|---|---|---|---|
| Локальный модульный монолит в настольном приложении | 0001 | сервер/SaaS, микросервисы, serverless | Работа офлайн, данные у пользователя, ACID без сети | Нет доступа с другого устройства, обновления у пользователя | Нужен постоянный доступ с нескольких устройств → ADR-0011 |
| Деньги — целые копейки, период — `YYYY-MM` | 0002 | float, decimal-string, диапазон дат | Точная арифметика, сортируемость | Запрет дробных копеек, сериализация `bigint` | Мультивалютность или иная точность |
| Квитанция, платёж и распределение — три сущности | 0003 | платёж на квитанцию, распределение в JSON | Частичная оплата, аванс, несколько квитанций на платёж | Больше связей и агрегатов | Продукт сводится к «оплата одной квитанции» |
| Идемпотентность по ключу операции | 0004 | дедупликация по сумме и дате, без дедупликации | Безопасные повторы импорта и будущей синхронизации | Клиент обязан генерировать ключ | Внешний источник не даёт стабильных идентификаторов |
| Локальная транзакция + журнал изменений | 0005 | event sourcing, синхронные вызовы, 2PC | События и синхронизация без dual-write | Append-only журнал и его очистка | Журнал выносится в отдельный контур |
| Профиль владельца и локальный доступ; модель готова к семье | 0006 | один пользователь без профилей, внешний identity-провайдер | Вход и аудит автора; задел на членов семьи без миграции | Пароли и восстановление доступа; роли пока не включены | Появляется многопользовательский режим (OQ? зона развития) |
| Неизменяемая зафиксированная квитанция, исправление — сторно | 0007 | правка на месте, мягкое удаление | История и аудит | Рост объёма, UI показывает пары «документ–сторно» | Требуется версионирование документов |
| Один файл SQLite со вложениями, миграции вперёд | 0008 | проприетарный формат, серверная БД, JSON-файл | Переносимость копированием, понятная копия | Две копии и блокировка файла, место на диске | Объём > 2 ГБ или совместная работа |
| Electron-установщики под Windows/macOS/Linux | 0009 | Tauri, Flutter, веб-версия | Единый TS-стек, одинаковый рендеринг | Размер установщика и памяти | Нужен мобильный клиент или экономия ресурсов |
| TypeScript + Electron + React + SQLite | 0010 | Tauri + Rust, .NET MAUI, Flutter | Один язык, зрелая экосистема, быстрый онбординг | Размер и потребление памяти | Смена платформы по ADR-0009 |
| Журнал изменений как основа будущей синхронизации | 0011 | CRDT сразу, синхронизация файлом, без синхронизации | Модель готова к облаку без переделки | Сложность конфликтов отложена, но заложена | Реальное включение синхронизации |
| Локальное OCR + правила + обязательное подтверждение | 0012 | облачный OCR, только ручной ввод, локальная ML-модель | Приватность, офлайн, нет оплаты за API | Точность ниже облака; шаблоны настраивает пользователь | Точность < 90 % (QS-11), формат не размечается (QS-12) или мобильный клиент |
| Один репозиторий: документация и код версионируются вместе | 0013 | отдельный репозиторий дизайна, раздельные воркспейсы | Одна история и один тег на версию, сквозные PR, сохранность документации | Репозиторий продукта содержит дизайн-историю; CI фильтрует пути | Открытие кода отдельно, рост команды, лимиты CI |

Решения без отдельного ADR (приняты в [core-modules.md](core-modules.md), меняются
с ревью): слои модуля и `api.ts` как единственная публичная точка (§3), модель
ошибок и доменные коды (§6), состав событий (§5), UUIDv7 и ISO-8601 UTC (§8),
роль `owner` и модель профилей/ролей (§9).

## 4. Как проверять артефакты

Диаграммы — производные от текста, проверяются рендером; ошибка синтаксиса
означает, что артефакт не существует.

```bash
# все диаграммы каталога (SVG + PNG рядом с источником)
pnpm diagrams

# одна диаграмма — быстрая проверка синтаксиса
node_modules/.bin/mmdc -i docs/design/architecture/components.mmd \
  -o /tmp/components.svg -p .tools/puppeteer-config.json -b white
```

Проверки, которые обязаны быть зелёными на ревью:

| Что проверяем | Как | Ожидаемый результат |
|---|---|---|
| Синтаксис и рендер всех `.mmd` | `pnpm diagrams` | exit 0, SVG у каждого источника |
| Нет циклов и запрещённых импортов между модулями | архитектурные тесты `tests/architecture/` | Тест падает при цикле или импорте внутренностей |
| Renderer не обращается к базе и `main/` | архитектурный тест по зависимостям | 0 нарушений |
| Каждая финансовая таблица имеет `id` и `created_at` | `validate-docs` | 0 исключений |
| Деньги и периоды соответствуют C-02/C-03 | `validate-docs` (`DBML_MONEY_TYPE`, `DBML_PERIOD_TYPE`) | Нет `float`/`numeric` в денежных колонках |
| Требования связаны с модулями и решениями | `validate-docs` (`IDS_FR_UNTRACED`) | Нет FR без модуля и ADR/инварианта |

## 5. Границы ответственности документов

- **Источник истины** — `.mmd`, `.dbml`, `.md` в git. `.svg`/`.png` — производные,
  руками не правятся (C-07).
- **Бриф** задаёт требования; архитектура не расширяет scope.
- **Допущения** помечены `A-NN` и перечислены там, где используются: A-01 — в
  брифе, A-02…A-07 — в [scaling.md](scaling.md), DM-A-01…DM-A-10 — в
  [entities.md](../domain/entities.md).
- **Открытые вопросы** OQ-01…OQ-06 остаются у пользователя; архитектура фиксирует,
  какое решение от них зависит.

## 6. Статусы и изменения

Все ADR в этой поставке — `proposed`: проработка завершена, решение принимает
владелец продукта на ревью. Статус меняется по правилам
[adr/README.md](adr/README.md) §2; изменение принятого решения оформляется новым
ADR со ссылкой `Заменяет: ADR-NNNN`, а не правкой старого.
