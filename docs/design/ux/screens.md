# Экраны и информационная архитектура

Список экранов выводится из сценариев [scenarios.md](scenarios.md). Каждый экран
имеет назначение, действия и состояния; инварианты проверяет сервер, экран только
показывает результат и объясняет отказ.

## 1. Навигация

```
Вход / выбор профиля
└── Главная (сводка, напоминания)
    ├── Объекты → Объект
    ├── Справочники (группа, свёрнута по умолчанию)
    │   └── Типы объекта
    ├── Поставщики
    ├── Лицевые счета
    ├── Услуги → Тарифы
    ├── Начисления (импорт CSV — после первой версии)
    ├── Квитанции → Квитанция, Распознавание (S-26), Шаблоны (S-27)
    ├── Платежи → Платёж → Распределение
    ├── Счётчики → Показания
    ├── Напоминания
    ├── Отчёты
    └── Данные (бэкап, экспорт, восстановление)
Настройки
├── Профили и права
├── Напоминания и окна
├── Шифрование и безопасность
└── О приложении, обновления
```

Группа «Справочники» свёрнута по умолчанию и остаётся в том же состоянии на
время работы приложения; выбор пункта внутри группы раскрывает её и подсвечивает
пункт. Сейчас в группе один пункт — «Типы объекта»; позже туда добавятся услуги,
тарифы и другие справочники, чтобы меню не разрасталось.

## 2. Экраны

### S-01 — Вход

Выбор профиля и пароль; «Создать файл данных», «Открыть файл». Ошибки: неверный
пароль, файл не найден, файл новее приложения, повреждённый файл. **FR-14.**

Визуально — титульный лист ([design-system.md](design-system.md) §5.2): знак и
пояснение слева, форма справа, вертикальная линейка между ними. Шапка окна общая
с остальными экранами.

### S-02 — Первый запуск

Мастер: выбор папки для файла, создание первого профиля (`owner`), краткая
подсказка «что дальше». **FR-14, FR-16.**

### S-03 — Главная

Сводка: долг и переплата по объектам, ближайшие напоминания, последние платежи,
быстрые действия. Пустое состояние — подсказка добавить объект. **FR-08, FR-11, FR-13.**

### S-04 — Объекты

Список с фильтром по типу и поиском, архив. Действия: добавить, открыть,
архивировать. **FR-01.**

Визуально — реестр ([design-system.md](design-system.md) §5.3): шапка колонок,
строки через линейку, табличные цифры. Строка реестра открывает объект (S-05);
архивирование вызывается на экране объекта, потому что колонка действий ломала
реестр на минимальной ширине окна.

Типы объекта живут в отдельном справочнике (S-04a), он открывается из группы
«Справочники» в левом меню. Если в справочнике не осталось ни одного типа,
«Добавить объект» по-прежнему доступно: тип создаётся прямо в форме объекта.

### S-04a — Типы объекта

Справочник типов, которые выбираются в карточке объекта. Колонки: название типа
и число объектов, которые его используют (активные и архивные вместе), с
названиями до пяти объектов. Действие «Удалить» есть у каждого типа.

Удаление разрешено только для типа, которым не пользуется ни один объект.
Занятый тип показывает, сколько объектов и какие именно его используют, а
кнопка удаления недоступна с подсказкой «Удалить тип можно, только когда им не
пользуется ни один объект». Свободный тип удаляется после инлайн-подтверждения
«Удалить тип «X»? Действие необратимо.»; удаление пишется в `change_log` и
`audit_event` (`property.type.delete`). Встроенные пять типов удаляются на тех
же условиях. Архивные объекты считаются использованием: пока объект в архиве,
его тип удалить нельзя. **FR-01.**

### S-05 — Объект

Карточка: название, тип, адрес, площадь, доля, лицевые счета, баланс, история
документов. **FR-01, FR-03, FR-08.**

Форма открывается отдельным листом вместо реестра: хлебные крошки «Объекты /
Объект», поля, действия справа. Архивный объект — только для чтения, с действием
«Вернуть в активные». Возврат — «Отмена», «Закрыть» или Esc; фокус возвращается
на строку, открывшую лист.

Новый тип создаётся не в справочнике, а вместе с объектом. «+» в поле «Тип
объекта» только добавляет черновик в список и показывает подсказку «Тип «X»
появится в справочнике после сохранения объекта». main создаёт тип в той же
транзакции, что и объект: «Выйти без сохранения», Esc и ошибка сохранения не
оставляют типа в справочнике. Если тип с таким названием уже есть (регистр не
важен), используется он; скрытый тип возвращается в выбор. Тот же порядок
действует при редактировании существующего объекта.

Если в форме есть несохранённые изменения (правка поля, открытая форма нового
типа, введённое имя типа или выбранный черновик типа), все пути закрытия —
«Отмена»/«Закрыть», Esc и крошка «Объекты» — сначала показывают
инлайн-подтверждение «Изменения не сохранены» с действиями «Продолжить
редактирование» и «Выйти без сохранения». Esc в подтверждении возвращает в
форму и не закрывает лист. После успешного сохранения, архивации или
восстановления подтверждение не появляется.

### S-06 — Поставщики

Список: название, тип, контакты, число лицевых счетов. **FR-02.**

### S-07 — Лицевые счета

Список по объекту и поставщику, номер, состояние; ссылка на личный кабинет
поставщика и памятка по передаче показаний/оплате; закрытие при долге запрещено.
**FR-03, FR-19, INV-12.**

### S-08 — Услуги

Справочник услуг: название, единица, категория. **FR-04.**

### S-09 — Тарифы

История тарифов по услуге с датами действия; форма нового тарифа; пересечение
даты отклоняется. **FR-04, INV-04.**

### S-10 — Начисления

Список за период с фильтрами (объект, услуга, источник), сумма за период.
**FR-05.**

### S-11 — Начисление

Форма: лицевой счёт, услуга, период, сумма, основание; подсказка о копейках.
**FR-05, INV-01, INV-02.**

### S-12 — Импорт CSV (после первой версии)

Мастер: файл → сопоставление колонок → предпросмотр → импорт → отчёт
(`created`/`duplicate`/`rejected`) с причинами. Отложен решением R-06.
**FR-05, QS-03.**

### S-13 — Квитанции

Список за период: статус, сумма, срок оплаты, остаток. **FR-06.**

### S-14 — Квитанция

Карточка: строки с основанием (начисление), итог, срок, статус, оплаченная
информация (дата/комментарий), вложения, история. После `issued` — только чтение;
действия «Аннулировать» (с причиной) и «Сторно»; после `void` — «Выпустить заново».
**FR-06, FR-12, FR-15, INV-03, INV-05.**

### S-15 — Платежи

Список платежей с фильтрами по дате и счёту; сумма распределена/не распределена.
**FR-07, FR-08.**

### S-16 — Платёж и распределение

Форма платежа с выбором квитанций; сохранить без выбранной квитанции нельзя
(INV-22); FIFO или вручную; остаток платежа — аванс; панель отмены распределения
с причиной. Ошибка «превышает остаток» — с пояснением.
**FR-07, FR-08, INV-07…INV-10, INV-22.**

### S-17 — Счётчики

Список приборов: серийный номер, услуга, срок поверки, состояние. **FR-09.**

### S-18 — Показания

Показания по счётчику за периоды; форма ввода; предупреждение об убывании с
подтверждением и причиной; отдельная операция «Заменить счётчик» с начальным
показанием; отметка «передано» со временем автоматически, опционально дата и
способ; срок поверки. **FR-09, FR-10, INV-14, INV-15.**

### S-19 — Напоминания

Список активных и закрытых; действия «выполнено», «отложить», «отключить вид».
**FR-11.**

### S-20 — Отчёты

Период и разрез (услуга, объект); суммы, график, таблица; экспорт. **FR-13.**

### S-21 — Вложения

Галерея миниатюр, просмотр, прикрепление и удаление с подтверждением; одно фото —
одно вложение, изображение сжимается при добавлении, проверка целостности по
`sha256` (R-01). **FR-12, INV-19.**

### S-22 — Данные

Две автокопии состояния (текущая и предыдущая) при запуске/закрытии с проверкой
целостности, «Сохранить копию», «Восстановить», «Экспорт CSV/XLSX/JSON». Архива
по годам в первой версии нет. **FR-16, QS-07.**

### S-23 — Профиль и права (зона развития)

В первой версии — один профиль `owner`; экран показывает его и пароль. Список
профилей, роли и отключение появятся вместе с многопользовательским режимом;
последний `owner` защищён. **FR-14, INV-16.**

### S-24 — Настройки

Тема, окна напоминаний (за сколько дней), формат дат, язык. Шифрования файла в
первой версии нет (OQ-02). **FR-11, C-04.**

### S-25 — Аудит

История изменений с фильтрами по профилю, дате, типу объекта; причина и
`correlation_id`. Только чтение. **FR-15, INV-17.**

### S-26 — Распознавание квитанции

Загрузка или перетаскивание файла; прогресс обработки; экран подтверждения:
изображение слева, извлечённые поля справа, строки услуг с суммами; уверенность
каждого поля; подсветка низкой уверенности; кнопки «Подтвердить», «Отклонить»,
«Использовать шаблон», «Настроить шаблон» (S-27), если формат незнаком. После
подтверждения — ссылка на созданную квитанцию.
**FR-18, INV-21, QS-11.**

### S-27 — Шаблоны квитанций

Список шаблонов по поставщикам: название, поставщик, версия, дата создания;
действия «Создать по скану», «Открыть», «Новая версия», «Архивировать». Редактор
разметки: скан/PDF образца слева, инструмент обводки областей; список полей
(период, поставщик, лицевой счёт, строки услуг, итог, срок оплаты); предпросмотр
«что распознано» без создания документов; сохранение новой версии — старые
остаются доступны (INV-23). Ошибки: область вне страницы, пустая или
пересекающаяся — подсветить и не сохранять. **FR-20, INV-23, QS-12.**

## 3. Сквозные требования к экранам

1. Все суммы вводятся и показываются в рублях с копейками; хранение — в копейках.
2. Опасные действия требуют подтверждения и причины; причина видна в аудите.
3. Ошибки формулируются действием: что произошло и что сделать.
4. Запрещённое действие роли либо скрыто, либо недоступно с объяснением.
5. Ни один экран не требует сети; индикатор «офлайн» не нужен.
6. Клавиатурная навигация и читаемые подписи — обязательны; проверяются в e2e.

## 4. Визуальная система и окно

Токены, типографика, раскладка и модель окна Electron зафиксированы в
[design-system.md](design-system.md). Экран не рисует собственный каркас: шапка
окна, навигация, плотность и состояния общие.

1. Заголовок окна — 38 px, кастомный (`titleBarStyle: 'hidden'`, системный
   светофор macOS, overlay Windows/Linux), целиком drag-регион, кнопки — `no-drag`
   (ADR-0020).
2. Тема по умолчанию светлая; в шапке окна — переключатель «светлая / тёмная /
   как в системе». Системный режим следует за ОС через `prefers-color-scheme`;
   ни один экран не выглядит недоделанным в тёмной теме.
3. Плотность: контролы 32–40 px, тело 13–15 px, шаг отступов 4/8; мобильных
   брейкпоинтов нет.
4. Проверочные размеры окна: 1180×760 по умолчанию, 900×640 минимум; размер,
   позиция и развёрнутость восстанавливаются между запусками.
5. Состояния обязательны на каждом экране: загрузка (скелетные строки), пусто,
   пусто после фильтра, ошибка с повтором, фокус, hover, disabled, busy.
6. Клавиатура: «К содержанию», видимый фокус, Enter/Space на строке реестра,
   ↑/↓/Home/End/Enter в выпадающем списке, Esc закрывает меню или лист формы и
   возвращает фокус на строку.
