# Пользовательские сценарии

Сценарии — проверяемое описание того, что делает человек. Каждый сценарий:
актор, цель, предусловие, шаги, ошибки, критерий приёмки, требования и экраны.
Ссылки на требования — [brief.md](../brief.md); экраны — [screens.md](screens.md).

## US-01 — Первый запуск и профиль

**Актор:** собственник (`owner`). **Цель:** начать вести учёт и защитить данные.
**Предусловие:** приложение установлено, файла данных ещё нет.
**Шаги:** выбрать «Создать файл данных» → указать папку → создать профиль (имя,
пароль) → войти → увидеть пустую главную с подсказкой «добавьте помещение».
**Ошибки:** папка недоступна — понятное сообщение и выбор другой; пароль слишком
короткий — требования показаны до ввода; файл уже существует — предложить открыть
или создать в другой папке.
**Приёмка:** файл создан, профиль сохранён, повторный запуск открывает тот же файл
и требует пароль. **Требования:** FR-14, FR-16. **Экраны:** S-01, S-02.

## US-02 — Помещение, поставщик и лицевой счёт

**Актор:** `owner`. **Цель:** завести объекты учёта.
**Предусловие:** вход выполнен.
**Шаги:** «Помещения» → добавить (квартира/дом/машиноместо, адрес, площадь, доля)
→ «Поставщики» → добавить (название, тип, контакты) → «Лицевые счета» → открыть
счёт (помещение × поставщик, номер) → при желании указать ссылку на личный кабинет
поставщика и памятку, куда передавать показания/оплачивать.
**Ошибки:** дубль лицевого счёта — показать существующий; пустое название — не
пропустить; удаление помещения с историей — только архивирование.
**Приёмка:** объекты видны в списках и доступны в формах начислений и платежей;
ссылка на ЛК и памятка открываются с карточки счёта.
**Требования:** FR-01, FR-02, FR-03, FR-19. **Экраны:** S-04, S-05, S-06, S-07.

## US-03 — Услуги и тарифы

**Актор:** `owner`. **Цель:** задать цены, чтобы понимать начисления и проверять
квитанции.
**Предусловие:** есть поставщик.
**Шаги:** «Типы услуг» → добавить (название, единица, категория) → «Услуги
поставщиков» → выбрать поставщика и тип услуги → «Тарифы» → указать цену и дату
начала → при изменении цены создать новый тариф, закрыв старый. Если тот же ресурс
продаёт другой поставщик, создаётся вторая услуга поставщика со своим тарифом.
**Ошибки:** пересечение дат — отклонить с объяснением; цена нецелая — подсказать
ввод в копейках/рублях; дубль типа услуги или пары «поставщик + тип» — показать
существующую запись.
**Приёмка:** на дату выбирается ровно один действующий тариф у каждой услуги
поставщика; старый не перезаписан; «Вода» от двух поставщиков имеет разные цены.
**Требования:** FR-04, INV-04. **Экраны:** S-08, S-08a, S-09.

## US-04 — Начисления за период

**Актор:** `owner`. **Цель:** внести суммы к оплате.
**Предусловие:** есть лицевой счёт и тип услуги.
**Шаги:** «Начисления» → выбрать период → добавить строку (лицевой счёт, услуга,
сумма) → сохранить; при необходимости использовать шаблон прошлого периода.
Начисления также создаются из подтверждённой квитанции (US-16).
**Ошибки:** сумма ≤ 0 — отклонить; период не `YYYY-MM` — не дать ввести; дубль
(тот же счёт, услуга, период) — показать существующую запись; исправление — сторно.
**Приёмка:** начисление видно в списке и в квитанции; повтор не создаёт дубля.
**Требования:** FR-05, INV-01, INV-02. **Экраны:** S-10, S-11.

## US-05 — Импорт начислений из CSV (после первой версии)

> Сценарий отложен решением R-06: в первой версии квитанции вносятся фото/сканом,
> PDF или вручную. Описание сохранено для будущего импорта.

**Актор:** `owner`. **Цель:** не вводить десятки строк вручную.
**Предусловие:** есть выгрузка из личного кабинета поставщика.
**Шаги:** «Начисления» → «Импорт» → выбрать файл → сопоставить колонки → просмотреть
предпросмотр → импортировать → увидеть отчёт (`created`/`duplicate`/`rejected`).
**Ошибки:** неверная кодировка/разделитель — подсказка; неизвестный лицевой счёт —
строка отклонена с причиной; повторный импорт — 0 новых записей.
**Приёмка:** число строк в отчёте равно числу строк файла; повтор безопасен.
**Требования:** FR-05, INV-13, QS-03. **Экраны:** S-12.

## US-06 — Квитанция и её фиксация

**Актор:** `owner`. **Цель:** получить документ за период и защитить его от правок.
**Предусловие:** есть начисления за период.
**Шаги:** «Квитанции» → «Сформировать за период» → проверить строки → указать срок
оплаты → «Зафиксировать» → увидеть статус `issued`.
**Ошибки:** квитанция уже существует — открыть её; сумма строк не сходится —
заблокировать фиксацию; правка после фиксации — предложить сторно.
**Приёмка:** после фиксации поля недоступны; сумма = сумма строк; изменение
попало в аудит. **Требования:** FR-06, INV-03, INV-05. **Экраны:** S-13, S-14.

## US-07 — Регистрация платежа

**Актор:** `owner`. **Цель:** отметить факт оплаты.
**Предусловие:** есть лицевой счёт.
**Шаги:** «Платежи» → «Добавить» → лицевой счёт, сумма, дата, канал, комментарий →
выбрать квитанции (одну или несколько) и суммы → сохранить: платёж и распределение
создаются вместе.
**Ошибки:** сумма ≤ 0 — отклонить; не выбрана ни одна квитанция — не сохранять
(INV-22); сумма больше остатка квитанции — ограничить, остаток станет авансом;
повторное нажатие «Сохранить» — вернуть тот же платёж; дата в будущем — предупредить.
**Приёмка:** платёж и активные распределения созданы одной операцией; аудит записан.
**Требования:** FR-07, INV-13, INV-22, QS-02. **Экраны:** S-15, S-16.

## US-08 — Распределение, долг и переплата

**Актор:** `owner`. **Цель:** понять, что закрыто, а что нет.
**Предусловие:** есть платёж и квитанции.
**Шаги:** выбрать платёж → при необходимости разнести оставшийся аванс
(«Распределить автоматически» FIFO или вручную) → сохранить → увидеть баланс
лицевого счёта; при ошибке — «Отменить распределение» с причиной.
**Ошибки:** сумма больше остатка квитанции — ограничить; больше платежа — отклонить;
конкурентная правка — предложить повторить; переплата — показать как аванс;
отмена распределения возвращает деньги в аванс.
**Приёмка:** сумма активных распределений ≤ платежа; баланс = начисления − оплаты;
аванс отражён; отмена распределения попала в аудит.
**Требования:** FR-08, INV-07…INV-10. **Экраны:** S-16, S-05.

## US-09 — Счётчики и показания

**Актор:** `owner`. **Цель:** вести приборы учёта.
**Предусловие:** есть лицевой счёт и тип услуги.
**Шаги:** «Счётчики» → добавить (серийный номер, установка, поверка, срок) →
«Показания» → выбрать период → ввести значение → сохранить.
**Ошибки:** значение меньше предыдущего — предупредить и запросить подтверждение
с причиной; дубль периода — открыть существующее; срок поверки истёк — отклонить
с объяснением; для реальной замены — отдельная операция «Заменить счётчик» с
начальным показанием.
**Приёмка:** показание одно на период; история поверок и срок видны; убывание без
подтверждения отклоняется.
**Требования:** FR-09, INV-14, INV-15. **Экраны:** S-17, S-18.

## US-10 — Передача показаний поставщику

**Актор:** `owner`. **Цель:** отметить, что показания внесены поставщику.
**Предусловие:** есть показание за период; в карточке счёта указано, куда передавать.
**Шаги:** «Показания» → выбрать → «Отметить переданным»: время отметки ставится
автоматически; при желании указать фактическую дату и способ (личный кабинет,
телефон, бумажно); ссылка на ЛК — из настроек счёта.
**Ошибки:** отметка на будущее — предупредить; повторная отметка — обновить время и
записать аудит.
**Приёмка:** отметка видна в списке и снимает напоминание; само показание не
изменилось; способ опционален. **Требования:** FR-10, FR-19. **Экраны:** S-18, S-07.

## US-11 — Напоминания

**Актор:** `owner`. **Цель:** не пропустить срок.
**Предусловие:** есть квитанции или счётчики.
**Шаги:** главный экран → блок «Напоминания» → выполнить/отложить/отключить;
настроить окна в «Настройках».
**Ошибки:** отключение всех напоминаний — подтверждение; выполненное напоминание
не удаляется, а закрывается.
**Приёмка:** напоминания создаются без дублей и закрываются действием.
**Требования:** FR-11. **Экраны:** S-03, S-19, S-24.

## US-12 — Скан квитанции или чека

**Актор:** `owner`. **Цель:** сохранить подтверждающий документ.
**Предусловие:** есть квитанция или платёж.
**Шаги:** открыть документ → «Прикрепить файл» → выбрать фото/скан → увидеть
миниатюру → при необходимости открыть на весь экран.
**Ошибки:** слишком большой файл — сжать с согласия; неподдерживаемый формат —
объяснить; повторное прикрепление того же файла — предупредить.
**Приёмка:** файл хранится в файле данных и доступен после перезапуска; одно фото —
одно вложение. **Требования:** FR-12, INV-19. **Экраны:** S-21.

## US-13 — Отчёты и графики

**Актор:** `owner`. **Цель:** понять, куда уходят деньги.
**Предусловие:** есть данные за период.
**Шаги:** «Отчёты» → выбрать период и разрез (услуга, помещение) → увидеть суммы и
график → при необходимости экспортировать.
**Ошибки:** нет данных — понятная пустая подсказка; отчёт строится долго —
индикатор и возможность отменить.
**Приёмка:** отчёт сходится с балансом; открытие ≤ 1 с на обычном объёме.
**Требования:** FR-13. **Экраны:** S-20.

## US-14 — Проверка истории изменений

**Актор:** `owner`. **Цель:** понять, кто и почему изменил документ.
**Предусловие:** есть операции.
**Шаги:** открыть документ → «История» → увидеть автора, время, действие, причину;
при необходимости отфильтровать по профилю и периоду.
**Ошибки:** история недоступна для гостя — скрыть; попытка изменить запись — запрет.
**Приёмка:** каждое финансовое изменение имеет запись; записи не редактируются.
**Требования:** FR-15, INV-17. **Экраны:** S-25.

## US-15 — Экспорт, бэкап и перенос

**Актор:** `owner`. **Цель:** не потерять данные и перенести на другое устройство.
**Предусловие:** вход владельца.
**Шаги:** «Данные» → «Сохранить копию» → выбрать папку; «Экспорт» → CSV/XLSX/JSON;
на новом устройстве — установить приложение, «Открыть файл данных», ввести пароль.
Две автокопии (текущая и предыдущая) создаются при запуске/закрытии с проверкой
целостности.
**Ошибки:** нет места на диске — сообщение; повреждённый файл — предложить копию;
версия файла новее приложения — отказ с объяснением.
**Приёмка:** копия восстанавливается; экспорт открывается без приложения; перенос
на другую ОС работает. **Требования:** FR-16, INV-20, QS-07. **Экраны:** S-22.

## US-16 — Квитанция с фото, скана или PDF

**Актор:** `owner`. **Цель:** внести квитанцию, не перебивая её вручную.
**Предусловие:** есть поставщик и лицевой счёт (или пользователь укажет их при
подтверждении).
**Шаги:** «Квитанции» → «Внести со скана» → выбрать фото/скан/PDF → дождаться
распознавания → на экране подтверждения проверить поля (период, поставщик,
лицевой счёт, строки услуг и суммы, итог, срок) → исправить подсвеченные поля →
подтвердить → получить черновик начислений (source = recognition) и квитанцию.
**Ошибки:** файл не читается — предложить другой; PDF без текстового слоя —
обработать как изображение; низкая уверенность — подсветить поле и не дать
подтвердить без проверки; поставщик не найден — предложить выбрать вручную;
формат незнаком — предложить настроить шаблон по этому скану (US-17);
отмена — не создавать финансовых записей.
**Приёмка:** финансовые документы не созданы до подтверждения; каждое поле и
каждая строка услуги имеют уверенность; исправления сохранены в аудите, шаблон не
меняется (INV-23, R-10); сеть не использовалась.
**Требования:** FR-18, INV-21, QS-11. **Экраны:** S-26.

## US-17 — Настройка шаблона квитанции по скану

**Актор:** `owner`. **Цель:** научить приложение распознавать новый формат
квитанции без ожидания обновления.
**Предусловие:** есть скан/фото квитанции незнакомого формата; известен поставщик
(или его можно создать).
**Шаги:** «Квитанции» → «Шаблоны» → «Создать по скану» → выбрать файл → указать
поставщика и название шаблона → обвести мышью области полей (период, поставщик,
лицевой счёт, итог, срок оплаты) и область таблицы услуг → увидеть предпросмотр:
что распознано в каждой области → поправить области → сохранить шаблон (версия 1)
→ при необходимости сразу перераспознать эту квитанцию.
**Ошибки:** область вне страницы или не задано обязательное поле — не сохранять с
объяснением; пустая или пересекающаяся область — подсветить; в области не найден
текст — предложить увеличить область или указать правило разбора; имя уже
существует — предложить новую версию с подтверждением; отмена — шаблон не создан.
**Приёмка:** шаблон создан без разработчика; на образце распознаются обязательные
поля; предпросмотр не создал финансовых документов; правка полей при обычном
распознавании шаблон не меняет (INV-23); старая версия не перезаписана.
**Требования:** FR-20, INV-23, QS-12. **Экраны:** S-27.

## Вне сценариев первой версии

FR-17 (синхронизация) — зона развития; сценарии появятся вместе с решением
включить синхронизацию (ADR-0011, OQ-04). Импорт CSV (US-05) отложен решением
R-06. Профили членов семьи и роли `member`, шифрование файла (OQ-02) и архив по
годам также отложены (см. brief §1, §3).
