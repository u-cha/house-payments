Этот каталог отвечает на вопрос «что человек делает в приложении и что он видит».
Архитектура и модель данных — в [../architecture/core-modules.md](../architecture/core-modules.md)
и [../domain/entities.md](../domain/entities.md); требования — в [../brief.md](../brief.md).

## Правила

1. Сценарий без обработки ошибок — незаконченный сценарий.
2. Экран не проверяет инварианты; он показывает решение сервера и объясняет отказ.
3. Все денежные значения в UI — рубли с копейками; в API и модели — копейки.
4. Опасные финансовые действия (сторно, аннулирование, восстановление из копии)
   требуют причины или подтверждения; действие попадает в аудит.
5. Приложение работает офлайн; ни один сценарий не требует сети.
6. В первой версии один профиль `owner`; роль `member`, её права и видимость
   действий появятся вместе с многопользовательским режимом (зона развития).
