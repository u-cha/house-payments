# Визуальная система и модель окна

Документ фиксирует визуальное направление приложения: токены, типографику,
раскладку, состояния и модель окна Electron. Он дополняет [screens.md](screens.md)
(что за экран) и [scenarios.md](scenarios.md) (что делает человек): здесь — как
это выглядит и почему именно так. Задача — редизайн визуального слоя M0-09/M0-11
без изменения доменной логики и IPC-контракта.

Направление выбрано из трёх мокапов (см. «Варианты и выбор»). Скиллы, по которым
собрано решение: `frontend-design` (направление и токены), `desktop-ui-electron`
(заголовок окна, drag-регион, состояние окна), `electron-development` (границы
процессов), `web-design-guidelines` (аудит готового UI).

## 1. Принципы

1. **Приложение — домовая книга, а не дашборд.** Плотная рабочая поверхность для
   учёта платежей за жильё: линейки, табличные цифры, спокойные поверхности.
   Никаких карточек с тенями, градиентов и «геройских» блоков.
2. **Числа — главный визуальный элемент.** Площадь, доля, суммы и периоды
   выравниваются по правому краю и набираются табличными цифрами
   (`font-variant-numeric: tabular-nums`), чтобы колонки не «плясали».
3. **Одна гарнитура с засечками для имён, одна без — для интерфейса.** Засечки
   читаются как печатный документ и отделяют «названия» от «управления».
4. **Смелость в одном месте.** Запоминающаяся деталь — двойная линейка и
   реестровая таблица; всё остальное тихо и служебно.
5. **Нативность важнее бренда.** Системные шрифты (работа офлайн), ширина окна
   без мобильных брейкпоинтов, клавиатура, обе темы ОС, восстановление окна.

## 2. Варианты и выбор

| Вариант | Суть | Почему не выбран |
|---|---|---|
| **A. «Реестр»** | Домовая книга: линейки, засечки, табличные цифры, акцент «штамп» | **Выбран.** Масштабируется на квитанции, платежи и счета; одинаково честен в обеих темах |
| B. «Пульт» | Тёмный консоль: рейка иконок, моно-метки, янтарный акцент | Тёмная тема как основная требует второй светлой «на равных», а «почти чёрный + один яркий акцент» — типовой дефолт |
| C. «Чертёж» | Техпаспорт: сетка, размерные выноски, master-detail | Меняет информационную архитектуру и объём работы; идея полезна точечно для S-05 позже |

## 3. Проверка на «дефолтность»

| Типовой AI-паттерн | Что сделано вместо |
|---|---|
| Кремовый фон + высококонтрастная антиква + терракота | Холодная бумага `#EEF1F2`, засечки только для имён и заголовков, акцент — петроль `#17545E` |
| Набор одинаковых скруглённых карточек с мягкой тенью | Реестровые линейки, одна панель-лист у формы; тень есть только у окна ОС |
| Почти чёрный фон + один кислотный акцент | Светлая тема по умолчанию, тёмная — системная; акцент приглушённый, не кислотный |
| ALL-CAPS надзаголовки и мета-строки через «·» | Подписи в нижнем регистре, тип и адрес — отдельные колонки, а не склейка через точку |
| «→» в кнопках, декоративные номера 01/02 | Действия называются глаголом без стрелок; нумерация не используется |
| Моноширинный шрифт для мелких меток | Моно — только для технического футера версии |

## 4. Токены

Токены живут CSS-переменными на `:root` и переопределяются в
`@media (prefers-color-scheme: dark)`. Имя переменной — роль, не цвет.

### 4.1 Цвет: ядро

| Роль | Светлая | Тёмная | Где |
|---|---|---|---|
| `--ink` | `#16202A` | `#E2E9EC` | основной текст |
| `--paper` | `#EEF1F2` | `#10171A` | фон содержимого |
| `--surface` | `#FFFFFF` | `#182126` | панель формы, поля, заголовок окна |
| `--rule` | `#C9D1D6` | `#2A363C` | линейки таблицы, границы |
| `--accent` | `#17545E` | `#6FB3BC` | основное действие, ссылки, фокус |
| `--danger` | `#9B2C2C` | `#E08C86` | ошибки, необратимые действия |

### 4.2 Цвет: производные

### 4.3 Контраст (проверено по WCAG 2.1)

| Пара | Отношение | Порог |
|---|---|---|
| `--ink` на `--paper` | 14,5 : 1 | AAA (7:1) |
| `--ink-muted` на `--paper` | 6,1 : 1 | AA+ |
| `--ink-faint` на `--paper` | 4,6 : 1 | AA для текста |
| Белый на `--accent` | 8,5 : 1 | AAA |
| `--accent` на `--paper` | 7,5 : 1 | AAA |
| `--danger` на `--paper` | 6,6 : 1 | AA+ |
| Тёмная тема: `--ink` / `--paper` | 14,8 : 1 | AAA |
| Тёмная тема: `--ink-muted` / `--paper` | 8,1 : 1 | AAA |
| Тёмная тема: `--ink-faint` / `--paper` | 5,2 : 1 | AA |

`--rule` и `--rule-strong` — нетекстовые, контраст 1,4–1,8 : 1; это линии, не
носители информации. Информация никогда не передаётся только цветом.

### 4.4 Типографика

| Роль | Гарнитура | Размер / интерлиньяж | Вес |
|---|---|---|---|
| Словесный знак | serif | 38 / 1,05 (вход), 13,5 (заголовок окна) | 400 |
| Заголовок страницы | serif | 31 / 1,1 (окно 1280), 28 / 1,1 (окно 900) | 400 |
| Заголовок листа | serif | 27 / 1,1 | 400 |
| Заголовок входа | serif | 24 / 1,15 | 400 |
| Заголовок блока | serif | 20 / 1,2 | 400 |
| Имя объекта в реестре | serif | 15 / 1,3 | 400 |
| Текст интерфейса | sans | 13,5 / 1,5 | 400 |
| Мелкий текст | sans | 12,5 / 1,45 | 400 |
| Микротекст, подсказки | sans | 11,5 / 1,45 | 400 |
| Шапка таблицы | sans | 10,5 / 1,2, трекинг 0,03em | 500 |
| Числа | sans + `tabular-nums` | 13–14 / 1,2 | 400 |

Гарнитуры только системные: работа офлайн и предсказуемость на macOS, Windows и
Linux. Стек:

```css
--font-display: 'Iowan Old Style', 'Palatino Linotype', Palatino, Georgia, serif;
--font-ui: -apple-system, BlinkMacSystemFont, 'Segoe UI', 'Helvetica Neue', Arial, sans-serif;
```

Засечки не используются для длинного текста и для контролов: только имена,
заголовки и словесный знак.

### 4.5 Шкала отступов и размеров

- Отступы: `2 · 4 · 8 · 12 · 16 · 20 · 24 · 32 · 40` px.
- Поле страницы: 28–34 px по горизонтали (900 px — 22–26 px), 20–28 px сверху.
- Боковая навигация: 220 px при окне ≥ 1120 px, 200 px при 900–1119 px.
- Ширина листа формы: 580 px, но не более ширины содержимого.
- Высота контролов: 32 px в списке и тулбаре, 34–36 px в формах и входе.
- Строка реестра: 44 px (900 px) / 48 px (1280 px).
- Радиусы: 3 px — контролы, 4 px — листы и панели, 10 px — окно ОС.
- Линии: 1 px обычная, 3 px double — раздел шапки страницы.

### 4.6 Движение

- Переходы только на цвет и фон: 120 ms `cubic-bezier(.2, 0, 0, 1)`.
- Нет входных анимаций, параллакса и декоративных циклов.
- `prefers-reduced-motion: reduce` отключает переходы полностью.

## 5. Раскладка

### 5.1 Каркас окна

```
┌──────────────────────────────────────────────────────────────┐ 38 px, drag
│ ● ● ●  house-payments │ Объекты          Владелец   Выйти   │
├──────────────┬───────────────────────────────────────────────┤
│ Главная      │  Объекты                         [+ Объект]   │
│ ▍Объекты     │  Квартиры, дома, машиноместа и участки.       │
│ Поставщики   │  ═══════════════════════════════════════════  │ 3px double
│ Квитанции    │  [Поиск…] [Тип: все] [Активные|Архив]         │
│ Платежи      │  ─────────────────────────────────────────    │
│              │  Название        Тип       м²       Доля      │
│              │  ─────────────────────────────────────────    │
│              │  Карабайка 36…   квартира  54,2 м²  100%      │
│  (футер)     │  ─────────────────────────────────────────    │
└──────────────┴───────────────────────────────────────────────┘
```

Регионы: заголовок окна фиксирован 38 px; навигация фиксирована; прокрутка —
только в области содержимого. Ширина содержимого ограничена 980 px, выравнивание
по левому краю (не по центру), потому что реестр читается как документ.

### 5.2 Вход (S-01)

```
┌──────────────────────────────────────────────────────────────┐
│ ● ● ●  house-payments                            Вход        │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│   house-                     │  Вход                          │
│   payments                   │  Профиль: Владелец             │
│   Учёт платежей за жильё     │                                │
│   ═══════════════════════    │  Пароль                        │
│                              │  [●●●●●●●●●●●●●●]              │
│   Квартиры, дома и участки…  │  [        Войти        ]       │
│                              │                                │
│   Данные хранятся только на этом компьютере        v0.0.0    │
└──────────────────────────────────────────────────────────────┘
```

Две колонки: слева «титульный лист» (знак, подзаголовок, двойная линейка,
пояснение), справа форма. Между ними вертикальная линейка. На узком окне
(900 px) колонки 330 / 1px / остальное, при 900 px содержимое не сжимается ниже
300 px на форму.

### 5.3 Список объектов (S-04)

Реестр без карточек: шапка колонок, строки через линейку, hover — белая подсветка.
Строка — кнопка: клик открывает объект (S-05) в режиме просмотра/правки. Действие
«В архив» живёт на экране объекта, а не в строке: на 900 px колонка действий
ломала реестр. Пустое состояние — заголовок с засечками, одно предложение и
основное действие.

### 5.4 Объект и форма (S-05)

```
Объекты / Новый объект
Новый объект                    ← serif 27
════════════════════════════════════════════  ← 3px double
┌──────────────────────────────────────────┐
│ Название                                 │
│ [Карабайка 36, кв. 12]                   │
│ Тип объекта              [квартира ▾] [+]│
│ Адрес                                    │
│ [Карабайка, 36]                          │
│ Площадь, м²        Доля владения, %      │
│ [Необязательно]    [100]                 │
│                    От 0,01 до 100…       │
│                        [Отмена] [Создать]│
└──────────────────────────────────────────┘
```

Форма — лист на бумаге, а не карточка поверх списка: список и форма не
показываются одновременно. Переход «список → лист» с хлебными крошками и
возвратом по «Отмена»/Esc. Кнопки справа, основное действие крайнее справа
(конвенция macOS).

## 6. Окно Electron

### 6.1 Модель заголовка

- `titleBarStyle: 'hidden'`; на macOS светофор остаётся системным,
  `trafficLightPosition: { x: 16, y: 13 }` под полосу 38 px.
- HTML-заголовок: `-webkit-app-region: drag`, `user-select: none`; все
  интерактивные элементы внутри — `no-drag` (кнопка «Выйти», профиль).
- Windows/Linux: `titleBarOverlay: { height: 38, color, symbolColor }`,
  системные кнопки справа, наши контролы не заходят в их зону. Цвета оверлея
  обновляются по событию `nativeTheme.updated`.
- Заголовок не содержит собственного «закрыть/свернуть»: системные контролы
  остаются системными.

### 6.2 Состояние окна

- Файл `window-state.json` в `app.getPath('userData')`; поля: `x`, `y`,
  `width`, `height`, `isMaximized`.
- Сохранение: на `close` (до диалога выхода) и с задержкой 300 ms после
  `resize`/`move`.
- Восстановление: только если сохранённые границы пересекаются хотя бы с одним
  текущим дисплеем; иначе — значения по умолчанию.
- Размер по умолчанию 1180×760, минимум 900×640. 900×640 — проверочный размер:
  реестр, вход и форма обязаны помещаться без горизонтальной прокрутки.

### 6.3 Темы

- `nativeTheme.themeSource = 'system'`; renderer получает тему через
  `@media (prefers-color-scheme: dark)`.
- Обе темы равноправны: ни один экран не должен быть «светлым по умолчанию».
- Смена темы ОС не перезапускает приложение и не теряет состояние форм.

### 6.4 Границы процессов

- `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true` — без
  изменений.
- Предзагрузка и IPC-контракт (`src/shared/ipc.ts`) не меняются: тема и
  состояние окна не требуют новых каналов.
- Код окна — только `src/main/**`; визуальный слой — только
  `src/renderer/**`.

## 7. Состояния и взаимодействие

| Состояние | Вид |
|---|---|
| Hover | фон `--paper-soft` / `--surface`, без сдвигов и теней |
| Focus | `outline: 2px solid var(--accent); outline-offset: 2px` — всегда виден |
| Active/pressed | `--accent-strong` или фон `--accent-soft` |
| Disabled | `opacity: .55`, `cursor: not-allowed`, `aria-disabled` где нужно |
| Busy | `aria-busy`, текст «Сохранение…», курсор `progress` только у кнопки действия |
| Loading списка | 3 скелетные строки цветом `--rule`, `aria-busy` на контейнере |
| Empty | заголовок serif, одно предложение, одно действие |
| Пусто после фильтра | «Ничего не найдено» + «Сбросить фильтры» |
| Error | баннер `--danger-soft` / `--danger-border`, `role="alert"`, код ошибки микротекстом |
| Field error | текст `--danger` под полем, `aria-invalid`, `aria-describedby` |

## 8. Клавиатура и доступность

- Первый Tab — ссылка «К содержанию» (визуально скрыта до фокуса).
- Порядок: заголовок окна (только реальные кнопки) → навигация → тулбар →
  реестр → основное действие.
- Строка реестра — кнопка: Enter/Space открывает объект; фокус остаётся в
  списке после возврата.
- Esc закрывает лист формы и возвращает фокус на кнопку, открывшую его.
- Ошибки объявляются `role="alert"`; загрузка — `aria-busy`.
- Все действия доступны без мыши; системные сочетания (⌘C, ⌘V, ⌘Q) не
  переопределяются.
- Цели нажатия ≥ 28×28 px; текст не мельче 11,5 px.

## 9. Реализация

- `apps/desktop/src/renderer/styles.css` — токены и стили; один файл, без новых
  зависимостей и UI-фреймворков.
- `apps/desktop/src/renderer/components.tsx` — общие `TitleBar`, `ErrorBanner`,
  `EmptyState`.
- `apps/desktop/src/main/window-state.ts` — сохранение/восстановление окна,
  чистые функции для тестов.
- `apps/desktop/src/main/main.ts` — `titleBarStyle`, `trafficLightPosition`,
  `titleBarOverlay`, `nativeTheme`.
- Домен, IPC и preload не меняются.

## 10. Границы и неприкосновенное

- Без новых UI-фреймворков и шрифтовых файлов.
- Без изменения IPC-контракта, доменных правил и инвариантов.
- Без отключения `contextIsolation`/`sandbox`.
- Остальные 23 экрана получают токены и каркас, но их состав — в следующих
  задачах; этот документ задаёт систему, а не рисует все экраны.
