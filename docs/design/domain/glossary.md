# Глоссарий предметной области

Единый словарь терминов. Если термин встречается в документах или коде — он
означает ровно то, что написано здесь. Синонимы в скобках допустимы в UI, но не в
коде и не в модели данных.

## Сущности учёта

| Термин | Определение | Не путать с |
|---|---|---|
| **Профиль** (`profile`) | Учётная запись члена семьи в приложении: имя, роль, пароль. Данные всех профилей лежат в одном файле. | Пользователь облака |
| **Роль** (`role`) | Права профиля: `owner` — полный доступ; `member` — будущая роль для членов семьи, в первой версии не создаётся. | Должность |
| **Помещение** (`property`) | Объект учёта: квартира, дом, машиноместо или другой тип недвижимости; в интерфейсе называется «объект». | Лицевой счёт |
| **Тип объекта** (`property_type`) | Редактируемый справочник типов: «Квартира», «Дом», «Машиноместо», «Земельный участок»; пользователь может добавить свой тип. | Категория услуги |
| **Доля владения** (`share_bp`) | Часть объекта, принадлежащая пользователю, в базисных пунктах: 10000 = 100 %. | Площадь |
| **Поставщик** (`supplier`) | Организация, выставляющая начисления: УК, ТСЖ, ресурсоснабжающая организация. Не удаляется, а уходит в архив (`is_active`); одинаковые названия допустимы и лишь предупреждаются. | Платёжная система |
| **Лицевой счёт** (`account`) | Номер, по которому поставщик ведёт учёт объекта; уникален в паре «объект + поставщик». Хранит ссылку на ЛК и памятку; закрывается датой `closed_on`. | Банковский счёт |
| **Услуга** | Вид начисления: ХВС, ГВС, электроэнергия, содержание, вывоз ТКО. В модели разделена на тип услуги (что потребляется) и услугу поставщика (кто и на каких условиях оказывает). | Тариф |
| **Тип услуги** (`service_type`) | Ресурс общего справочника: «Вода», «Тепло», «Электроэнергия». Название уникально без учёта регистра; единица измерения задаётся здесь. Архив — `is_active`. | Услуга поставщика |
| **Услуга поставщика** (`supplier_service`) | Конкретная услуга у конкретного поставщика: «Вода от РСО Лютик». Пара «поставщик + тип услуги» уникальна; у неё своя история тарифов и архив (`is_active`). | Тип услуги |
| **Тариф** (`tariff`) | Цена за единицу услуги поставщика, действующая с даты. Версионируется: старый не перезаписывается, а закрывается днём до начала нового. `unit` — снимок единицы, сумма — в копейках. | Начисление |
| **Единица измерения** (`unit`) | Код единицы услуги и тарифа: `m3` (м³), `gcal` (Гкал), `kwh` (кВт·ч), `person` (чел.), `m2` (м²), `month` (мес.), `piece` (шт.). Список фиксирован, расширяется только миграцией. | Количество |
| **Архивирование записи** (`is_active`, `closed_on`) | Скрытие записи справочника из выбора без физического удаления: счета, начисления и история сохраняются. Для лицевого счёта архив — `closed_on`. | Архив (файл данных) |
| **Расчётный период** (`period`) | Месяц начисления в формате `YYYY-MM`. | Дата платежа |
| **Начисление** (`accrual`) | Сумма к оплате по услуге за период. Основание квитанции. | Платёж |
| **Квитанция** (`invoice`) | Документ за период: сумма, срок оплаты, состояние. После фиксации не редактируется. | Начисление |
| **Строка квитанции** (`invoice_line`) | Детализация квитанции по услуге. | Начисление |
| **Платёж** (`payment`) | Факт уплаты денег. Не привязан к квитанции напрямую. | Распределение |
| **Распределение** (`allocation`) | Отнесение суммы платежа на квитанцию. Один платёж — несколько распределений. | Платёж |
| **Переплата / аванс** (`advance_minor`) | Неразнесённый остаток платежей на лицевом счёте. Может быть распределён позже. | Долг |
| **Долг** (`debt_minor`) | Неоплаченная часть начислений по лицевому счёту. | Переплата |
| **Баланс** (`balance`) | Текущее состояние лицевого счёта: начислено, оплачено, долг, переплата. | Остаток на карте |
| **Сторно** (`reversal`) | Отмена документа обратной записью. Исходный документ остаётся. | Удаление |
| **Счётчик** (`meter`) | Прибор учёта в помещении для типа услуги: серийный номер, дата установки, дата поверки, срок действия. К поставщику не привязан, поэтому смена поставщика его не трогает. | Показание |
| **Показание** (`meter_reading`) | Значение счётчика за период и дата снятия; хранит, какому поставщику оно передано. | Начисление |
| **Поверка** (`verification`) | Проверка счётчика с датой и сроком действия; история хранится в `meter_verification`, после истечения срока показания не принимаются. | Гарантия |
| **Отметка о передаче** (`submission_marked_at`) | Признак и время того, что показание внесено поставщику (лично, по телефону, в личном кабинете или иным способом); способ и фактическая дата — опционально. | Показание |
| **Напоминание** (`reminder`) | Задача со сроком: оплатить, передать показания, пройти поверку. | Уведомление от поставщика |
| **Вложение** (`attachment`) | Файл (скан, фото, чек), прикреплённый к документу; хранится в том же файле данных (BLOB) как сжатая копия (R-01). | Квитанция |
| **Аудит-запись** (`audit_event`) | Неизменяемая запись: кто, когда, что и почему изменил. | Журнал изменений |

## Распознавание квитанций

| Термин | Определение | Не путать с |
|---|---|---|
| **Распознавание** (`recognition`) | Локальное извлечение данных из фото, скана или PDF квитанции: период, поставщик, лицевой счёт, услуги, суммы. | Ручной ввод |
| **Задание импорта** (`import_job`) | Одна загруженная квитанция (фото, скан, PDF) или, после первой версии, один CSV-файл, проходящий обработку. | Вложение |
| **Кандидат распознавания** (`recognition_candidate`) | Поле, извлечённое из изображения, с уверенностью и координатами; не финансовый документ до подтверждения. | Начисление |
| **Шаблон поставщика** (`supplier_template`) | Версионируемые области полей и правила разбора квитанций конкретного поставщика; создаётся пользователем в модуле настройки по скану, версии не перезаписываются, без самообучения (FR-20, INV-23, R-10). | Тариф |
| **Уверенность** (`confidence_bp`) | Оценка надёжности распознанного поля в базисных пунктах: 10000 = максимальная. | Точность модели |

## Данные и переносимость

| Термин | Определение |
|---|---|
| **Файл данных** | Один файл SQLite (`.hpd`), содержащий все данные и вложения пользователя. Переносится копированием. |
| **Резервная копия** | Снимок файла данных, пригодный для восстановления. |
| **Архив** | Зона развития: вынос старых лет в отдельный файл при росте основного файла. В первой версии архива нет — все данные в одном файле; выгрузка для переноса/чтения без приложения — это экспорт. |
| **Переносимость** | Свойство: данные можно выгрузить, перенести на другое устройство и открыть новой версией приложения. |
| **Синхронизация** | Обмен изменениями между устройствами через облако; в первой версии отсутствует, но модель к ней готова. |
| **Журнал изменений** (`change_log`) | Append-only последовательность изменений сущностей с логическими часами; основа будущей синхронизации. |
| **Миграция** | Изменение схемы файла данных, применяемое только вперёд при запуске новой версии. |
| **Версия схемы** (`schema_version`) | Номер применённой миграции; приложение отказывается открывать файл новее себя. |
| **Личный кабинет** (`cabinet_url`) | Ссылка на сайт поставщика, где можно передать показания или оплатить; хранится в настройках лицевого счёта вместе с памяткой. |

## Технические термины

| Термин | Определение |
|---|---|
| **Минорные единицы** | Целое количество копеек. Все денежные суммы хранятся и передаются так. |
| **Денежная сумма** (`Money`) | Value object: `amount_minor: bigint` + `currency`. Арифметика только между одинаковыми валютами. |
| **Период** (`Period`) | Value object `YYYY-MM` с операциями `next()`, `previous()`, сравнением. |
| **Bounded context** | Граница модели и языка: внутри — свои термины и правила, снаружи — только контракт. |
| **Модуль ядра** | Пакет с явным публичным контрактом и запретом на импорт внутренностей другого модуля. |
| **Порт** | Интерфейс, который ядро объявляет для внешнего мира (репозиторий, файловое хранилище, часы). |
| **Адаптер** | Реализация порта в конкретной технологии (SQLite, файловая система, IPC). |
| **Fitness function** | Исполняемая проверка, удерживающая архитектурное свойство (например, «нет циклических импортов»). |
| **Идемпотентность** | Свойство операции: повтор с тем же ключом не создаёт нового эффекта. |
| **Локальный модульный монолит** | Один процесс, одна база, жёсткие границы модулей внутри процесса. |

## Правила словоупотребления

1. «Квитанция» — всегда документ `invoice`; «лицевой счёт» — всегда `account`;
   банковский счёт — `bank_account`, и в первой версии он не моделируется.
2. «Оплата» — факт `payment`; «распределение оплаты» — `allocation`.
3. «Удалить» в финансовом контуре не существует: есть `reversal` (сторно) и
   `void` (аннулирование зафиксированной квитанции).
4. «Период» без уточнения — расчётный период `YYYY-MM`, а не интервал дат.
5. Все суммы в документации указываются в копейках, если не сказано иное.
6. «Семья» — группа профилей в одном файле данных, а не организация и не тенант.
7. «Архив» в контексте записи справочника — `is_active`/`closed_on` (скрытие без
   удаления); «архив» в контексте файла данных — вынос старых лет (зона развития,
   §5). Физического удаления записей справочников нет.
