# AGENTS.md — правила работы в этом репозитории

Один репозиторий = DSH-воркспейс `house-payments`: проектная документация и код
приложения живут вместе и версионируются вместе. Читайте этот файл перед любым
изменением; правила ниже не рекомендации, а границы.

## 1. Что где лежит

| Путь | Что это | Кто меняет |
|---|---|---|
| `docs/design/` | Проектные артефакты: бриф, ADR, домен, архитектура, UX, roadmap, трассировка. Источник истины по решениям. | дизайн/архитектура; правки — любая задача, которая меняет решение |
| `archive/` | Прежние проработки (SaaS-версия). Не действуют, не исправляются «под текущее». | только при явной задаче об архиве |
| `apps/desktop/` | Код приложения (Electron: main/preload/renderer, модули из `core-modules.md`). Создаётся с E-01. | только задачи на код |
| `apps/*/`, `packages/*/` | Будущие пакеты pnpm-воркспейса. | задачи на код |
| `scripts/`, `tests/` | Проверки артефактов и рендер диаграмм. | задачи на инструменты/проверки |
| `.dsh/skills/` | Симлинки на вендоренные скиллы. | не редактировать руками: `pnpm bootstrap` |
| `skills.lock.json` | Закреплённые версии вендоренных скиллов. | только вместе с проверкой, что скилл грузится |
| `third_party/` | Клоны чужих репозиториев. **В git не входит.** | никто: только `pnpm bootstrap`; руками не править |
| `.dsh-worktrees/` | Рабочие деревья изоляции задач DSH. **В git не входит.** | никто |

Правило границ: **код — только в `apps/`/`packages/`, проектные решения — только в
`docs/`**. Нельзя «по-быстрому» положить код в `docs/` или описание решения в
`apps/`.

## 2. Команды

```bash
pnpm install            # зависимости инструментов документации
pnpm bootstrap          # восстановить third_party/ и .dsh/skills/ после свежего клона
pnpm check              # validate + тесты; обязательное условие любого изменения
pnpm validate           # только проверки артефактов
pnpm diagrams           # отрендерить .mmd/.dbml в .svg/.png (результат не коммитится)
```

Новый клон: `git clone`, затем `pnpm install`, затем `pnpm bootstrap` — иначе
скиллы проекта будут битыми симлинками.

## 3. Git: правила, которые нельзя нарушать

1. **`main` защищён.** Прямые коммиты в `main` не делаются; работа идёт в ветке,
   результат попадает в `main` только через pull request.
2. Имя ветки: `<тип>/<id-задачи>-<краткий-слаг>`, где тип — `feat`, `fix`, `docs`,
   `chore`, `refactor`, `test`; `<id-задачи>` — id карточки доски (`t-…`) или
   номер issue. Пример: `docs/t-mw279jn2-repo-policy`.
3. Коммит — Conventional Commits: `feat: …`, `fix: …`, `docs: …`, `chore: …`,
   `refactor: …`, `test: …`. Заголовок до 72 символов, тело объясняет **почему**,
   а не что. В теле — строка `Task: <id задачи>`.
4. Атомарность: один логический смысл на коммит; сгенерированные файлы не
   коммитятся.
5. Запрещено: `git push --force` в `main`; переписывание истории `main`;
   `git clean -xdf` в корне (сотрёт `third_party/`, `node_modules/` и кэш);
   коммит `node_modules/`, `third_party/`, `.dsh-worktrees/`, `.env*`, секретов,
   `*.svg`/`*.png` под `docs/` (это производные).
6. PR: заголовок по Conventional Commits, описание — что/зачем/как проверено/
   остаточные риски; зелёный `pnpm check` (и CI, когда появится); squash-merge,
   ветка удаляется. Merge в `main` подтверждает владелец репозитория.

## 4. Документация и решения

1. Решение, которое меняет архитектуру, домен или процесс, оформляется ADR в
   `docs/design/architecture/adr/` по правилам журнала. Принятый ADR не
   переписывается: новое решение — новый ADR со ссылкой «Заменяет: ADR-NNNN».
2. Изменение решения в одном PR обновляет **все** затронутые артефакты: бриф,
   трассировку, roadmap, инварианты, README-навигацию. `pnpm check` это проверяет
   частично, остальное — ответственность автора.
3. Диаграммы — только из текстовых источников (`.mmd`, `.dbml`). Руками
   отредактированный `.svg` считается ошибкой.
4. Пользовательская документация (установка, руководство) появится в `docs/user/`
   в E-12 и версионируется тем же тегом, что и код.

## 5. Что считается завершённой работой

- Задача выполнена, `pnpm check` зелёный, изменения закоммичены в ветку и
  описаны в PR.
- Затронутые артефакты (`docs/design/**`, ADR, трассировка) обновлены в том же
  изменении.
- Секретов, абсолютных путей этой машины и артефактов сборки в коммите нет.
- Отчёт по задаче доски содержит: что изменено, как проверено, остаточные риски.
