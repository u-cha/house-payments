# Глоссарий предметной области

Единый словарь терминов. Если термин встречается в документах или коде — он
означает ровно то, что написано здесь. Синонимы в скобках — допустимые в UI,
но не в коде и не в модели данных.

## Основные сущности

| Термин | Определение | Не путать с |
|---|---|---|
| **Организация** (`tenant`) | Юридическое лицо, владеющее данными в системе: УК, ТСЖ, ЖК, расчётный центр. Граница изоляции данных. | Плательщик |
| **Дом** (`building`) | Здание с адресом, обслуживаемое организацией. | Помещение |
| **Помещение** (`property`) | Учитываемый объект: квартира, дом, машиноместо. Имеет вид (`property_kind`), площадь, номер. | Лицевой счёт |
| **Лицевой счёт** (`account`) | Финансовый учётный регистр помещения у организации. Начисления, счета и платежи привязаны к лицевому счёту, не к помещению напрямую. Открывается и закрывается. | Помещение, банковский счёт |
| **Плательщик** (`payer`) | Физическое или юридическое лицо, которое платит. Связывается с помещением через роль (собственник, наниматель, член семьи). Один плательщик — много помещений; одно помещение — несколько плательщиков. | Житель (роль доступа) |
| **Услуга** (`service`) | Вид начисления: ХВС, ГВС, электроэнергия, содержание, вывоз ТКО и т. п. Справочник уровня организации. | Тариф |
| **Тариф** (`tariff`) | Цена за единицу услуги, действующая с даты. Версионируется; старый тариф не переписывается. | Начисление |
| **Расчётный период** (`period`) | Месяц начисления в формате `YYYY-MM`. | Дата платежа |
| **Начисление** (`accrual`) | Сумма к оплате по лицевому счёту за услугу за период. Документ-основание для счёта. | Счёт |
| **Счёт / квитанция** (`invoice`) | Документ, выставленный плательщику: период, сумма, срок оплаты, состояние. После выставления не редактируется. | Начисление |
| **Строка счёта** (`invoice_line`) | Детализация счёта по услугам: услуга, сумма, основание расчёта. | Начисление |
| **Платёж** (`payment`) | Факт поступления денег от плательщика или из внешнего источника. Не привязан к счёту напрямую. | Распределение |
| **Распределение** (`allocation`) | Отнесение суммы платежа на конкретный счёт. Один платёж — много распределений; сумма распределений ≤ суммы платежа. | Платёж |
| **Аванс** (`credit_balance`) | Неразнесённый остаток платежа на лицевом счёте. Может быть распределён позже. | Переплата по счёту |
| **Пени** (`penalty`) | Начисление за просрочку оплаты. Отдельный вид требования, не смешивается с основным долгом. | Штраф |
| **Сторно** (`reversal`) | Операция, отменяющая действие документа обратной записью. Исходный документ остаётся в истории. | Удаление, редактирование |
| **Сверка** (`reconciliation`) | Сопоставление платежей из внешнего источника (банк, эквайринг) с записями системы. | Импорт |
| **Идемпотентность** (`idempotency`) | Свойство операции: повторный вызов с тем же ключом не создаёт нового эффекта. | Повторная попытка |

## Технические термины

| Термин | Определение |
|---|---|
| **Тенант** | Синоним организации как единицы изоляции; в коде — `tenant_id`. |
| **Минорные единицы** | Целое количество копеек. Все денежные суммы хранятся и передаются так. |
| **Денежная сумма** (`Money`) | Value object: `amount_minor: bigint` + `currency`. Арифметика только между одинаковыми валютами. |
| **Период** (`Period`) | Value object `YYYY-MM` с операциями `next()`, `previous()`, сравнением. |
| **Bounded context** | Граница модели и языка: внутри — свои термины и правила, снаружи — только контракт. |
| **Модуль ядра** | Пакет с явным публичным контрактом и запретом на импорт внутренностей другого модуля. |
| **Порт** | Интерфейс, который ядро объявляет для внешнего мира (репозиторий, шлюз платежей). |
| **Адаптер** | Реализация порта во внешней технологии (PostgreSQL, банк, HTTP). |
| **Outbox** | Таблица исходящих событий, пишется в одной транзакции с бизнес-изменением; доставка — отдельно. |
| **Аудит-запись** (`audit_event`) | Неизменяемая запись: кто, когда, какое действие, над каким объектом, с каким основанием. |
| **Fitness function** | Исполняемая проверка, удерживающая архитектурное свойство (например, «нет циклических импортов»). |

## Правила словоупотребления

1. «Счёт» — всегда документ `invoice`. «Лицевой счёт» — всегда `account`. В коде
   слово `account` не используется для банковского счёта — для него `bank_account`.
2. «Оплата» — факт `payment`; «распределение оплаты» — `allocation`.
3. «Удалить» в финансовом контуре не существует: есть `reversal` (сторно) и
   `void` (аннулирование до выставления).
4. «Период» без уточнения — расчётный период `YYYY-MM`, а не интервал дат.
5. UI-текст может говорить «квитанция», модель и API — только `invoice`.
6. Все суммы в документации указываются в копейках, если не сказано иное.
