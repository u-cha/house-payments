# Экраны и информационная архитектура

Список экранов выводится из сценариев [scenarios.md](scenarios.md). Каждый экран
обязан: показывать состояние (загрузка/пусто/ошибка/нет прав), не скрывать
финансовые операции без объяснения причины и не позволять действие, запрещённое
инвариантами. Деньги показываются в рублях с двумя знаками, хранятся в копейках.

## 1. Информационная архитектура

```
Организация (переключатель)
├─ Обзор
├─ Реестр
│  ├─ Дома
│  ├─ Помещения
│  ├─ Лицевые счета  ── карточка счёта (5 вкладок)
│  └─ Плательщики
├─ Начисления
│  ├─ Запуск начисления (мастер)
│  ├─ Начисления за период
│  └─ Сторно
├─ Счета
│  ├─ Выставление за период (мастер)
│  └─ Журнал счетов ── карточка счёта
├─ Платежи
│  ├─ Журнал платежей
│  ├─ Регистрация платежа
│  ├─ Распределение
│  ├─ Импорт выписки
│  └─ Очередь сверки
├─ Отчёты (начисления, поступления, дебиторка)
├─ Аудит
└─ Настройки (организация, роли, услуги и тарифы)

Личный кабинет (роль resident)
├─ Мои помещения
├─ Период: начисления, счёт, платежи
└─ Квитанция PDF
```

## 2. Экраны организации

| # | Экран | Роли | Назначение | Ключевые данные | Действия | Состояния и ошибки |
|---|---|---|---|---|---|---|
| S-01 | Вход | все | Аутентификация | email, пароль / SSO | Войти, восстановить доступ | Неверные данные, блокировка, истёкшая сессия |
| S-02 | Обзор | admin, accountant, auditor | Что происходит сейчас | сумма начислений и поступлений за период, дебиторка, расхождения сверки | Перейти в разделы | Пусто (новая организация) с подсказкой «начните с дома» |
| S-03 | Дома | admin | Справочник домов | адрес, город, число помещений | Создать, изменить, архивировать | Дом с помещениями не удаляется; архив вместо удаления |
| S-04 | Помещения | admin | Справочник помещений | вид, номер, площадь, дом, лицевой счёт | Создать, изменить, открыть счёт | Дубликат номера в доме → `CONFLICT` |
| S-05 | Лицевые счета | admin, accountant, cashier | Реестр счетов и балансов | номер, помещение, плательщик, баланс | Открыть карточку | Пусто; фильтры по дому/долгу |
| S-06 | Карточка лицевого счёта | admin, accountant, cashier, auditor | Вся история по счёту | вкладки: Начисления, Счета, Платежи, Распределения, История | Сторно, принять платёж, выписка | Закрытый счёт: действия недоступны с объяснением |
| S-07 | Плательщики | admin | Физлица и связи с помещениями | ФИО, контакты, помещения, доля | Создать, связать, отвязать | Нельзя отвязать единственного плательщика без подтверждения |
| S-08 | Услуги и тарифы | admin | Справочник услуг и версий тарифов | услуга, цена за единицу, дата начала | Добавить тариф, закрыть версию | Перекрытие периодов → `BUSINESS_RULE` |
| S-09 | Мастер начисления | accountant | Провести начисление за период | период, услуги, число счетов, сумма | Черновик → Проверить → Провести | Нет тарифа: список пропусков; период закрыт → `CONFLICT` |
| S-10 | Начисления за период | accountant, auditor | Просмотр и сверка начислений | лицевой счёт, услуга, сумма, статус | Фильтр, экспорт, сторно | Частично проведённый прогон помечен явно |
| S-11 | Мастер выставления счетов | accountant | Выставить счета на период | период, срок оплаты, число и сумма | Подтвердить | Уже выставлено → `CONFLICT`; нулевые суммы пропускаются |
| S-12 | Журнал счетов | accountant, auditor | Все счета | номер, период, сумма, оплачено, состояние | Открыть, аннулировать | Аннулирование недоступно при распределениях |
| S-13 | Карточка счёта | accountant, auditor, resident (только свой) | Документ и его жизнь | строки, сумма, срок, распределения, история | Скачать PDF, аннулировать | Неизменяемый после выставления |
| S-14 | Журнал платежей | accountant, cashier, auditor | Все поступления | дата, лицевой счёт, сумма, канал, остаток | Открыть, распределить | Дубли не создаются (INV-13) |
| S-15 | Регистрация платежа | cashier, accountant | Ввести платёж | счёт, сумма, дата, канал, примечание | Сохранить, сохранить и распределить | Сумма ≤ 0; закрытый счёт; повторное сохранение возвращает тот же платёж |
| S-16 | Распределение платежа | cashier, accountant | Разнести сумму по счетам | платёж, список открытых счетов, остатки | Автораспределение FIFO, ручная правка | Превышение остатка счёта/платежа → `BUSINESS_RULE`; конкурентное изменение → перечитать |
| S-17 | Импорт выписки | accountant | Загрузить файл банка | файл, батч, счётчики строк | Загрузить, посмотреть предпросмотр, подтвердить | Битая строка не валит батч; дубли распознаются |
| S-18 | Очередь сверки | accountant | Разобрать несопоставленные строки | строка выписки, кандидаты, расхождение | Сопоставить вручную, отклонить | Расхождение фиксируется, а не замалчивается |
| S-19 | Отчёты | accountant, auditor, admin | Начисления, поступления, дебиторка | период, дом, корзины просрочки | Построить, выгрузить CSV | Данные read-model с отметкой актуальности |
| S-20 | Аудит | auditor, admin | История изменений | кто, когда, объект, действие, причина | Фильтры, открыть документ | Только чтение, записи неизменяемы |
| S-21 | Настройки организации | admin | Реквизиты, роли, услуги | название, ИНН, участники, роли | Пригласить, изменить роль, отозвать | Нельзя удалить последнего администратора |

## 4. Сквозные требования к интерфейсу

- **Доступность**: клавиатурная навигация, контраст ≥ 4.5:1, подписи к полям,
  ошибки объявляются скринридером; финансовые суммы не кодируются только цветом.
- **Ошибки**: показывается код и человеческое объяснение; `details.reason`
  переводится в текст; технические стектрейсы не показываются.
- **Опасные действия**: сторно, аннулирование, закрытие счёта требуют причины и
  явного подтверждения; кнопка неактивна с подсказкой, если инвариант запрещает.
- **Деньги**: всегда с валютой и знаком; отрицательные значения — явный минус и
  подпись «переплата/аванс», а не красный цвет без текста.
- **Периоды**: единый формат `ММ.ГГГГ` в UI, `YYYY-MM` в API и модели.
- **Ответственность**: UI не является местом проверки прав и инвариантов — он
  лишь отражает решения сервера.
